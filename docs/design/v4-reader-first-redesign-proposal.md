# V4 "Reader-First" 재설계 제안서

> **상태: 설계안 (코드 미반영).** 이 문서는 `frontend-redesign-v4-reader-first` 브랜치에서 작성된 설계 보고서이며, 이 문서 자체는 앱 코드를 변경하지 않습니다. `docs/design/ui-guidelines.md`(화면별 역할/카드/버튼/시오리 배치 규칙)와 `docs/design/shiori-design-spec.md`(캐릭터 조형/에셋 운영)를 기반 규칙으로 삼고, 그 위에서 V4가 무엇을 더 밀고 나갈지를 정리합니다. 실제 구현은 14장의 3단계 계획을 따로 승인받은 뒤 진행합니다.

## 0. 지금 코드 기준 (읽은 것)

이 브랜치는 `cb4c9f0`(landing-copy-seo-polish 병합) 시점 상태입니다. 확인한 파일: `HomeDashboard.tsx`, `ReadingTab.tsx`, `ReaderMode.tsx`, `StudySection.tsx`, `VocabSection.tsx`, `SharedDeckSection.tsx`, `InfoSection.tsx`, `AnalyzeSection.tsx`, `globals.css`(카드/토큰/버튼 관련 규칙), `docs/design/ui-guidelines.md`, `docs/design/shiori-design-spec.md` 전문.

이 시점 코드에는 이미 아래와 같은 "관리 화면" 냄새가 남아 있습니다 — V4가 정확히 겨냥해야 할 지점입니다.

- `ReadingTab.tsx`: `ReaderRestoreBanner` + `ReaderCompactToolbar`(원문 관리 토글, 저장 가능/바구니 chip)가 리더 카드 위에 별도 관리 바로 얹혀 있음.
- `ReaderMode.tsx`: 단어를 선택하지 않은 "idle" 상태에 `token-sheet-overlay-idle` + `ShioriGuideCard`가 데스크톱 전용 고정 패널로 항상 떠 있음 — 원문과 별개의 두 번째 박스.
- `AnalyzeSection.tsx`(분류 탭): 읽기 탭과 거의 동일한 입력→토큰화 파이프라인을 별도 탭·별도 카드 언어(`classify-stage`, `classify-word-card`)로 다시 구현 — `ui-guidelines.md` 2장이 이미 "읽기 탭과 중복되는 별도 분석 도구 느낌 금지"를 명시.
- `InfoSection.tsx`(통계 탭): 역할은 "일지"이지만 `StatsPanel`(숫자 그리드)이 여전히 복습 탭 접힌 상세에도 중복 존재.
- `SharedDeckSection.tsx`: 카드 리스트 자체는 서가스럽지만, 상세 보기로 들어가면 등록일/작성자/가져간 횟수/공유 취소가 한 화면에 몰려 관리 패널로 바뀜.
- `VocabSection.tsx`: 덱 관리/CSV·JSON 백업/사용자 정의 용어 관리가 "더보기" 뒤에 있긴 하지만, 열리는 순간 노트 탭 안에 통째로 펼쳐짐(별도 화면 분리 없음).

## 1. V4 디자인 컨셉 한 줄

**"여러 기능 화면의 모음이 아니라, 한 권의 독서 노트 안에서 읽기 → 담기 → 복습이 끊기지 않고 이어지는 하나의 흐름."**

앱을 여는 이유는 항상 "원문을 읽고 싶어서"이고, 나머지 6개 화면은 전부 그 읽기 행위의 앞(입력)·뒤(담기·복습·서가·기록)에 붙는 곁다리라는 것을 화면 구조 자체가 말해야 합니다.

## 2. V4 전체 IA 제안

### 안 A — 현재 7탭 유지

책상 / 읽기 / 복습 / 분류 / 노트 / 덱 / 통계

- 장점: 네비게이션 변경 없음, 기존 사용자 학습 비용 0, 리스크 최소.
- 단점: `분류`와 `읽기`가 같은 파이프라인을 두 번 구현(코드 중복 + "어느 탭에서 원문을 다뤄야 하나" 혼란), `통계`가 `복습` 탭 접힌 상세와 내용이 겹침. 7개 라벨은 모바일에서 2글자 제한(`ui-guidelines.md` 7장)을 계속 강제.

### 안 B — 5탭으로 축소 (추천)

**책상 / 읽기 / 복습 / 노트 / 덱**

- `분류`는 별도 탭이 아니라 **읽기 탭 안의 보조 모드**로 흡수: 원문을 붙여넣은 뒤 "이어서 읽기"(현재 리더 모드) / "카드로 빠르게 분류"(현재 분류 탭의 스와이프 카드 UI) 두 가지 보기 중 고르는 토글. 데이터·토큰화 파이프라인이 원래 동일하므로 자연스럽습니다.
- `통계`는 별도 탭이 아니라 **복습 탭의 2번째 섹션**("오늘의 일지")으로 흡수: 복습 완료 카드 아래, 또는 복습 탭 하단에 접힌 형태로. `StudySection.tsx`가 이미 `<details className="study-stats-collapsible">`로 `StatsPanel`을 접어 넣는 패턴을 갖고 있어 확장이 자연스럽습니다.
- 하단 탭이 5개로 줄면 라벨에 여유가 생겨 2글자 제한을 완화할 수 있고, 터치 타깃도 넓어집니다.

**추천 이유**: 핵심 루프(읽기→담기→복습)가 정확히 3개 탭(읽기/노트/복습)에 1:1로 대응하고, 책상은 입구, 덱은 순수 보조 서가로 역할이 더 선명해집니다. `분류`와 `통계`는 원래도 "역할 한 줄"이 다른 화면의 보조 기능에 가까웠던 것들(`ui-guidelines.md` 2장 표 참고)이라, 흡수해도 기능이 사라지는 게 아니라 자리만 옮기는 것입니다.

**리스크**: 하단 탭 구조 변경은 되돌리기 어렵고(딥링크/사용자 습관), 두 기능의 발견성이 낮아질 수 있음 → **이번 단계에서는 제안으로만 남기고, 실제 전환은 3단계 계획의 마지막 단계에서 별도 승인 후 진행**(사용자 지시대로 이번 문서에서는 코드 변경 없음).

## 4. 화면별 새 레이아웃 구조

공통 골격: **상단(맥락 1줄) → 본문(주인공 1개) → 주요 CTA 1개 → 보조 액션(접힘 우선) → empty/loading/success(`AppEmptyState` 고정)**.

| 화면 | 상단 | 본문 | 주요 CTA | 보조 액션 | empty/loading/success |
|---|---|---|---|---|---|
| 책상 | 인사 한 줄(제목 없음) | 히어로 카드(3 CTA) + 요약 3칩 + 최근 단어 3장 | 원문 읽기 시작 | 오늘 복습하기 / 샘플 체험 | 최근 단어 0개 → 섹션 자체 미노출(별도 empty 없음) |
| 읽기(입력 전) | "원문 읽기" eyebrow만 | 원문 카드 1장(placeholder에 예시 내장) | 원문 읽기 시작 | 샘플로 체험(텍스트 링크급) | 없음(카드 자체가 늘 존재) |
| 읽기(분석 중) | 동일 카드 유지 | 같은 카드가 진행률 오버레이로 전환 | 분석 취소 | — | loading 문구 1줄 |
| 읽기(결과) | 진행률 바(옵션 뒤 토글) | 리더 텍스트 90% | 담은 단어로 학습 | 전체 저장 옵션(접힘) | — |
| 복습(대기) | 오늘 복습 준비 히어로 | CTA 타일 4개 | 오늘 복습 시작 | 학습 옵션(접힘) | 대상 없음 → `empty` mood 1장 |
| 복습(진행) | 없음(chrome 숨김) | 카드 1장 | 평가 4버튼 | 이전 | — |
| 복습(완료) | 완료 스탬프 | 완료 통계 5칸 + (V4) 일지 섹션 | 다시 복습 | 원문 읽기 / 노트 보기 | — |
| 노트 | 압축 히어로(칩 행) | 색인 카드 리스트 | 이 덱 학습하기 | 원문 읽기 / 더보기(관리) | 검색 결과 없음 / 단어 없음 각각 `empty` |
| 덱 | 서가 히어로 | 표지 카드 그리드 | 학습 목록에 추가 | 상세 보기 | 로딩 `loading`, 없음 `empty` |
| (분류→읽기 모드) | "카드로 분류" 토글 | 카드 1장 스와이프 | 4지 분류 | 이전 카드 | 전체 분류 완료 → 결과 요약 |
| (통계→복습 일지) | "오늘의 일지" 라벨 | 문장형 타임라인 + 덱별 진행 | 없음(정보 화면) | 자세히 보기(접힘) | 기록 없음 → `empty` |

## 5. 읽기 탭 redesign 상세 (V4의 핵심)

### 입력 전 상태
- 카드는 **1개**: `panel-card hero-card card-stack-surface` 조합 하나로 통일(이미 `ui-guidelines.md` 4장 modifier 체계 재사용, 새 클래스 없음).
- textarea는 화면을 지배하지 않게 4~5줄 높이로 시작하고 포커스 시에만 살짝 확장. placeholder 자체에 예시 문장을 담아 "샘플 안내 박스"를 아예 없애는 것을 목표(현재 있는 `ShioriCharacter mood="reading"` + "샘플로 체험" 버튼 조합은 카드 안 1줄 보조 행으로만 축소, 별도 박스 금지).
- **주요 CTA 1개**: "원문 읽기 시작"(primary, 클래스 없는 기본 버튼). 보조는 "샘플로 체험"뿐이고 `ghost-button` 이하로.
- 시오리는 이 화면에 **없어도 됨**(10장 참고) — 원문이 주인공이라는 원칙을 가장 먼저 이 화면에서 지킴.

### 분석 중 상태
- 별도 로딩 카드를 새로 띄우지 않고, 같은 원문 카드가 그대로 "분석 중" 표시로 전환(텍스트 흐릿하게 + 진행률 바). 청크 분석 시 진행률 바 + "분석 취소"만 노출.

### 읽기 모드 상태
- 헤더 최소화: 제목("읽기 모드") 자체도 생략 가능 — 탭 이름이 이미 "읽기"이므로 화면 안에서 또 말할 필요 없음. 진행률 바 + "옵션" 버튼만 상단에.
- 색상 범례(`reader-legend`)는 상시 노출 대신 `?` 아이콘 뒤 툴팁/팝오버로 뺌 — 처음 1회만 노출 후 기억.
- 원문 관리(원문 접기/새 원문/복원 알림)는 전부 "옵션" 팝오버 안 하위 그룹으로. 화면 최상단에 별도 툴바(`ReaderCompactToolbar`)를 만들지 않음.

### 단어 클릭 패널
- 데스크톱: 원문을 가리는 오버레이 대신, 가능하면 **원문 옆 인라인 사이드 패널**(2단 레이아웃, 원문 60% + 패널 40%)로 전환 검토. 오버레이 유지가 더 안전하면 최소한 "idle 상태의 고정 안내 패널"(`token-sheet-overlay-idle`)은 완전히 제거 — 아무것도 선택 안 했을 때는 패널이 존재하지 않는 것이 맞음(빈 박스보다 없는 게 낫다).
- 모바일: 기존 bottom-sheet 유지.

### 하단 action dock
- 한 줄 요약 + 버튼 1~2개만 항상 보임: "담은 단어 N개" + primary "저장한 단어로 바로 학습". "빠르게 전체 저장"(부분 저장 옵션들)은 기본 접힘.
- 후보 목록(`ReadingVocabPanel`)은 dock 바로 아래, 같은 카드 계열의 연장선처럼 붙임(별도 박스 아님).

### 토큰 하이라이트 규칙 (V4 표준으로 승격)
- 4색 고정: 아는(민트/세이지) · 헷갈리는(라벤더) · 모르는(코랄베이지) · 미분류(아이보리베이지). **빨강·회색·경고 느낌 금지**를 문서 규칙으로 명문화(지금은 코드 주석에만 있음).
- 하이라이트는 항상 파스텔 그라디언트 + 점선 밑줄, 진하게 채우지 않음. hover/active만 살짝 진해짐.
- JLPT 배지는 항상 하이라이트보다 한 단계 더 조용하게(현재보다 더 작아도 됨) — 정보량이지 강조점이 아님.

## 6. 복습 탭 redesign 상세

- 히어로: "오늘 복습 시작" CTA 1개 크게 + 진행률 한 줄. 나머지 3개 퀵스타트 타일은 유지하되 히어로보다 약하게.
- 학습 옵션(덱/모드 선택)은 기본 접힘 유지(현재도 `<details>`로 되어 있음 — 유지).
- 대기 중 empty: 시오리 1개 + 1~2줄 설명 + CTA 3개 이하.
- 진행 중: 다른 chrome 전부 숨김(현재 `isReviewingActive` 로직 유지) — 이 부분은 이미 V4 방향과 일치, 유지.
- 완료: 통계 5칸 유지, 그 아래 **(V4 신규)** "오늘의 일지" 섹션을 접힌 `<details>`로 추가 — `통계` 탭의 `StudyTimeline`/`DeckProgressJournal` 컴포넌트를 그대로 여기로 옮겨와 재사용(새로 만들지 않음).

## 7. 노트 탭 redesign 상세

- 히어로 칩 행은 유지, "더보기" 뒤 4개 액션(오늘 복습/덱 책장/단어 추가/덱·공유 관리)도 유지.
- 필터(`index-card-filter`)는 검색창만 항상 보이고, 상태 필터/정렬은 "필터" 토글 뒤로 한 단계 더 접는 것을 검토(현재는 이미 다 보임 — 리스트가 길어질수록 관리 화면처럼 보이는 원인).
- **덱 관리(삭제/생성)·백업(CSV/JSON)·사용자 정의 용어 관리**는 "더보기 → 덱·공유 관리"를 눌렀을 때 노트 탭 안에서 그대로 펼쳐지는 대신, **같은 화면이되 명확히 다른 표면**(예: 톤이 다른 `desk-surface` 대신 완전히 분리된 모달/서브페이지)으로 분리 검토 — 노트 탭 자체는 항상 "색인 카드 리스트"로만 보이게.

## 8. 덱 탭 redesign 상세

- 목록 카드는 표지(색) + 제목 + 단어 수 + "학습 목록에 추가" 버튼만. "상세 보기"를 눌러야 등록일/작성자/가져간 횟수/공유 취소가 보이도록(현재도 대부분 이렇게 되어 있음 — 유지).
- "내가 공유함" 표지 톤은 다른 두 톤(추천/공유 덱)과 같은 채도 레벨로 맞춤(청록이 유독 튀지 않게) — 3톤이 "같은 서가의 다른 책"처럼 보이게.
- 공유/구독 로직(임포트, subscribed lexeme progress 등)은 절대 변경하지 않음 — 표시 방식만.

## 9. 통계/학습 일지 redesign 상세

- 안 B(5탭) 기준: 독립 탭이 아니라 복습 탭 완료 화면 아래 "오늘의 일지" 접힌 섹션.
- 안 A(7탭 유지) 기준: 독립 탭 유지 시에도 리스트형 유지 — 표(table) 절대 금지, `records-word-row`/`records-deck-row` 카드 계열만 사용.
- 리스트가 5개를 넘으면 "더 보기"로 점진 노출(현재 이미 5개 슬라이스 — 유지), 새 복잡한 페이지네이션 만들지 않음.

## 10. 시오리 사용 규칙 재정의

기존 `shiori-design-spec.md`/`ui-guidelines.md` 6장 규칙(화면당 큰 시오리 1개, 버튼 안 금지, row 반복 금지)은 그대로 유지하고, V4에서 아래를 **추가**로 못박습니다.

1. **읽기 탭에는 큰 시오리를 두지 않는 것을 기본값으로 한다.** 원문이 유일한 주인공이어야 하는 화면이라, 입력 전 카드의 작은 보조 행 정도(또는 완전히 없음)가 원칙. 지금처럼 idle 상태에 상시 떠 있는 `ShioriGuideCard`는 제거.
2. **완료(success) 모먼트에는 항상 `ShioriStamp`만.** 화면급 `ShioriCharacter`를 완료 상태에 쓰지 않음(이미 규칙이지만 V4에서 재확인).
3. **empty state는 화면마다 최대 1개, `AppEmptyState` 경로로만.** 직접 마크업 금지 규칙 유지.
4. 새 variant/포즈 추가는 이번 V4 단계에서 없음(9종 안에서 해결).

## 14. 구현 3단계 계획

**1단계 — 읽기 탭 완성도 (탭 구조 변경 없음, 로직 변경 없음)**
`ReaderCompactToolbar`/idle 오버레이 제거, 입력 전 카드 단일화, action dock 경량화, 토큰 팔레트 확정. 리스크 가장 낮음(구조 변경 없이 순수 표현 정리) — 가장 먼저, 가장 빨리 체감 개선.

**2단계 — 나머지 6탭 톤 통일 (탭 구조 변경 없음)**
복습/노트/덱/통계/책상/분류 각각 11장 공통 규칙에 맞춰 카드 폭·여백·버튼 계층 정리. 여기까지는 안 A(7탭 유지)로도 완결된 결과물.

**3단계 — IA 재검토 (탭 구조 변경, 별도 승인 필요)**
안 B(5탭) 채택 여부 결정 → 채택 시 분류를 읽기 모드로, 통계를 복습 일지로 이전. 라우팅/딥링크/북마크된 탭 상태 영향 검토 후 별도 브랜치·별도 승인으로 진행. **이번 설계 단계에서는 코드 변경하지 않음.**

## 15. 리스크

- **하단 탭 구조 변경(안 B)은 되돌리기 어려움**: 사용자 탐색 습관, 저장된 딥링크/새로고침 시 탭 상태(`activeTab`)에 영향 — 반드시 별도 승인 후, 되돌릴 수 있는 방식(feature flag 없이 그냥 커밋 단위로 분리)으로 진행.
- **분류/통계 흡수 시 발견성 저하**: 두 기능이 "탭"이라는 눈에 보이는 자리에서 사라지므로, 흡수 후에도 진입 경로(예: 읽기 탭 안 토글, 복습 탭 안 섹션)가 최소 1탭 이내에서 바로 보여야 함 — 안 보이는 곳에 숨기면 실질적 기능 삭제와 같은 효과.
- **병행 작업과의 충돌**: 다른 브랜치(`frontend-visual-contrast-polish` 등)에서 진행 중인 CSS/컴포넌트 변경과 이 브랜치가 나중에 머지될 때 `globals.css`/`ReadingTab.tsx`/`ReaderMode.tsx`에서 충돌 가능성이 높음 — 실제 구현 착수 전 브랜치 정리 방향을 사용자와 먼저 확인 필요.
- **읽기 탭 구조 변경(1단계)도 상태 로직(선택 토큰, 복원 세션, 스크롤 위치)과 얽혀 있어** 순수 표현 변경이라도 prop 배선을 잘못 건드리면 기능 회귀 위험 — 구현 시 로직 함수는 그대로 두고 렌더 트리만 재배치하는 방식을 우선.
- **카드 최대폭 통일(11장)**은 일부 화면(분류 카드 720px 등)에서 실제 콘텐츠 밀도와 안 맞을 수 있어, 통일 전 화면별 실측 검토 필요.

## 16. 지금 코드에서 버릴 것과 유지할 것

**버릴 것**
- `ReaderCompactToolbar` 같은, 화면 최상단에 별도로 얹히는 "관리 바" 패턴 전반.
- 단어 미선택 상태에 상시 떠 있는 idle 안내 오버레이(`token-sheet-overlay-idle`).
- 화면마다 조금씩 다르게 손으로 짠 empty-state 마크업(있다면) — `AppEmptyState`로 전부 통일.
- `분류` 탭의 "별도 기능 화면" 정체성(안 B 채택 시) — 읽기 탭 모드로 흡수.
- `통계` 탭의 "별도 대시보드" 정체성(안 B 채택 시) — 복습 탭 일지 섹션으로 흡수.
- 토큰/필터 칩에 남아있는 빨강·회색류 배색(있다면) — 파스텔 4색으로 통일.

**유지할 것**
- 모든 백엔드/API/DB/SRS 로직, 원문 전체 미저장 정책, 데이터 모델 — 이번 설계는 프론트 표현·구조 전용.
- `AppEmptyState`, `ShioriCharacter`/`ShioriMark`/`ShioriStamp`/`ShioriGuideCard` 컴포넌트 체계와 9종 PNG 에셋.
- `panel-card`+modifier 카드 시스템, 버튼 계층(3단+destructive 3종), `records-word-row`/`index-card-filter` 등 이미 검증된 재사용 클래스.
- 복습 진행 중 chrome을 숨기는 `isReviewingActive` 패턴, 5개 슬라이스 등 이미 "적음이 낫다" 방향으로 맞춰진 기존 결정들.
- 하단 탭 7개(안 A 유지 시) 또는 5개(안 B 채택 시) 어느 쪽이든, 실제 라우팅/전환 로직 자체는 최소 변경으로 재사용.
