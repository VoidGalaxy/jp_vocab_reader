# Home Redesign Failure Manual

이 문서는 Home 탭 리디자인 반복 과정에서 왜 결과가 계속 좋아지지 않았는지,
어떤 실행착오가 있었는지, 다음 작업에서 같은 루프를 피하려면 어떤 방식으로
진행해야 하는지를 정리한 매뉴얼이다.

목표는 과거 작업을 비난하는 것이 아니라, 다음 Claude/Codex 작업자가
`Home`을 다시 만질 때 바로 판단 기준으로 쓰게 하는 것이다.

## 1. 핵심 실패 원인

Home 리디자인은 여러 번 진행됐지만 한동안 개선이 잘 일어나지 않았다. 가장 큰
원인은 "확정된 목표 장면 없이 현재 화면을 조금씩 고치는 방식"으로 계속 갔기
때문이다.

- 화면의 첫인상 문제가 구조 문제였는데, CSS 수치 조정으로 해결하려 했다.
- 그림자는 물리적 접지 문제였는데, `box-shadow`, SVG 타원, 검은 바, 투명
  shadow plate 같은 분리 레이어로 흉내내려 했다.
- 책, 탭, 배경, 캐릭터가 각각 따로 생성/배치되어 같은 조명 아래 놓인 물체처럼
  보이지 않았다.
- "목업과 비교"가 구현 전에 충분히 고정되지 않아, 매번 작업자가 자기 해석으로
  다른 부분까지 바꾸었다.
- 실패한 구조를 완전히 폐기하지 않고, 이전 phase의 흔적 위에 다음 phase를
  덧칠했다.

결론: Home은 작은 수치 조정으로 좋아지는 화면이 아니었다. 먼저 완성 목표
이미지를 정하고, 그 목표를 구현하는 방식으로 가야 했다.

## 2. 반복된 실행착오

### 2.1 Flat Coordinate Layout

초기 구조는 `note`, `CTA`, `notebook`, `shortcut`, `privacy`, `Shiori`가
각자 scene 기준 퍼센트 좌표로 배치되는 형태였다. 이 방식은 물리적 장면이 아니라
"종이 배경 위에 PNG들이 떠 있는 화면"으로 보였다.

실패 이유:

- 오브젝트들이 서로 같은 기준점에 묶이지 않았다.
- 책 위에 붙은 요소인지, 배경 위에 놓인 요소인지 관계가 불명확했다.
- 화면 폭이 바뀌면 접촉 관계가 깨졌다.

다음 원칙:

- Home의 모든 주요 오브젝트는 하나의 물리적 composite 안에서 관계를 가져야 한다.
- 특히 하단 tab은 scene 높이 기준이 아니라 notebook 기준으로 붙어야 한다.

### 2.2 Card/Mat Wrapper 회귀

중앙 rounded card, placemat, surface wrapper를 넣은 phase에서는 장면이
정리되는 듯했지만, 첫인상은 "앱 카드 안의 일러스트"가 되었다.

실패 이유:

- 목업의 핵심은 책상 위 물체인데, 카드 프레임이 먼저 읽혔다.
- 배경과 foreground가 하나의 공간이 아니라 패널 안팎으로 분리됐다.

다음 원칙:

- Home은 카드 안에 장면을 넣지 않는다.
- 배경은 scene frame이 아니라 desk surface 자체여야 한다.

### 2.3 CSS Lighting / Gradient Surface

radial-gradient, soft-light paper texture, ambient wash로 책상 표면을 만들려 했지만
반복 무늬와 사각형 경계가 드러났다.

실패 이유:

- CSS 라이팅은 실제 오브젝트 그림자와 맞지 않았다.
- scene 박스 높이에서 끝나는 wash가 패널처럼 보였다.
- 배경 소품과 빛 방향이 foreground와 따로 놀았다.

다음 원칙:

- desk surface는 가능하면 하나의 래스터 배경으로 고정한다.
- 조명은 배경과 foreground의 방향이 일치해야 한다.
- scene 자체에 끝나는 사각형 wash를 만들지 않는다.

### 2.4 Shadow Layer 실패

가장 오래 반복된 문제는 그림자였다. 책과 탭이 책상 위에 놓인 느낌을 만들기 위해
CSS 그림자, SVG 타원, shadow-only PNG, alpha shadow, edge softener 등을
시도했지만 대부분 실패했다.

실패 이유:

- 그림자가 물체의 실제 외곽에서 나온 것이 아니라 별도 도형처럼 보였다.
- 그림자 외곽 falloff가 부족해 박스형, 검은 줄, 떠 있는 판처럼 보였다.
- 책과 탭이 각각 따로 그림자를 가져서 서로 다른 높이에 떠 있는 것처럼 보였다.
- 책 하단 검은 edge와 그림자가 섞여 "접지"가 아니라 "오염된 바"처럼 보였다.

다음 원칙:

- 자연스러운 접지감이 핵심이면, 책+탭+그림자를 가능하면 한 장의 baked scene
  plate로 만든다.
- 그림자는 책 가까이는 진하고, 멀어질수록 부드럽게 사라지는 falloff가 있어야 한다.
- 하단 탭 그림자는 각 탭 아래에 따로 있지만, 방향과 농도는 책 그림자와 같은
  광원 규칙을 따라야 한다.
- 검은색 바, 직사각형 shadow plate, 과한 blur ellipse는 금지한다.

### 2.4.1 그림자 피드백 루프에서 배운 것

그림자 문제는 단순히 "더 진하게" 또는 "더 흐리게"의 문제가 아니었다. 사용자가
계속 요구한 것은 목업처럼 책과 탭이 책상 위에 실제로 닿아 있는 접지감이었다.
하지만 여러 phase에서 피드백을 잘못 해석해 같은 실패가 반복됐다.

반복된 피드백:

- "그림자가 안 보인다"
- "책상 위에 있는 느낌이 아니라 공중에 떠 있다"
- "하단의 검은색 줄이 그대로다"
- "그림자 외곽이 부자연스럽다"
- "책 가까이는 진하고 멀어지면 희미해져야 한다"
- "탭 그림자 위치가 목업과 다르다"

잘못된 대응:

- 그림자를 단순히 더 진하게 만들었다.
- 그림자 레이어를 더 크게 만들었다.
- 별도 SVG 타원이나 PNG shadow plate를 추가했다.
- 하단 edge를 가리려고 검은 바/softener를 얹었다.
- 책 그림자와 탭 그림자를 따로 만들면서 같은 광원과 높이 규칙을 맞추지 못했다.

왜 실패했는가:

- 목업의 그림자는 물체에서 자연스럽게 나온 cast shadow인데, 구현은 물체 아래에
  도형을 깔아둔 형태였다.
- 그림자의 가장 진한 부분이 책의 하단/오른쪽 접촉부에 붙어 있지 않았다.
- 멀어질수록 투명해지는 falloff가 부족하거나 방향이 맞지 않았다.
- 탭은 책보다 낮은 층에 있어야 하는데, 그림자 처리는 책과 같은 높이 또는 별도
  높이처럼 보였다.
- 책 하단의 어두운 edge와 shadow가 분리되지 않아, 접지 그림자가 아니라 검은 줄로
  인식됐다.

결정적으로 배운 점:

- 그림자는 "레이어 하나 추가"가 아니라 물리적 장면의 일부다.
- 책, 탭, 배경, 광원이 한 번에 결정되지 않으면 자연스러운 그림자가 나오기 어렵다.
- 사용자가 말한 그림자는 장식 그림자가 아니라 "책이 책상 위에 놓였다는 증거"다.

다음 작업의 그림자 처리 절차:

1. 먼저 목표 목업에서 그림자의 방향을 읽는다. 현재 Home 기준 광원은 좌상단,
   그림자는 하단/우측으로 떨어져야 한다.
2. 책 그림자의 가장 진한 영역을 책 하단 edge와 오른쪽 edge 바로 옆에 붙인다.
3. 하단 탭은 각 탭 바로 아래에 짧은 contact shadow를 갖되, 책 shadow보다 낮고
   작게 만든다.
4. 먼 그림자는 넓고 부드럽게 확산시키되, 가장자리 형태가 사각형이나 타원으로
   읽히지 않게 한다.
5. 검은 줄처럼 보이는 edge shadow는 실패로 보고 제거한다.
6. 투명 shadow-only 에셋을 만들기 어렵다면, 책+탭+그림자를 한 장의 baked scene
   plate로 합성한다.
7. QA는 "그림자가 존재하는가"가 아니라 "책과 탭이 책상에 닿아 보이는가"로 판단한다.

그림자 합격 문장:

> 책 하단과 오른쪽에는 진한 접촉 그림자가 붙어 있고, 책에서 멀어질수록 그림자가
> 부드럽게 풀린다. 하단 3개 탭도 각각 책상에 닿는 작은 그림자를 가지며, 검은
> 바나 박스형 그림자는 보이지 않는다.

### 2.5 Asset Mismatch

기존 에셋을 계속 재사용하려 했지만, 일부는 목표 목업에 맞지 않았다.

실패 이유:

- 기존 책 에셋 주변의 털/거스러미가 확대 화면에서 보였다.
- 탭 색이 서로 침범하거나 경계가 지저분했다.
- 배경과 책의 채도/명도가 맞지 않아 합성처럼 보였다.
- Shiori가 기존 위치에 들어가도 크기/자세가 애매하면 떠 보였다.

다음 원칙:

- "기존 에셋 사용"은 목표에 부합할 때만 한다.
- 맞지 않는 에셋은 재생성하거나 baked scene에 통합한다.
- Shiori는 표지 위 장식이 아니라, 종이/테이프 뒤에서 일부만 가려지는 물리적
  캐릭터로 넣는다.

## 3. 해결을 위해 바꾼 방식

반복 실패 후 접근을 바꿨다.

기존 방식:

1. 현재 화면을 본다.
2. 문제처럼 보이는 CSS 수치를 고친다.
3. 스크린샷을 보고 또 다른 수치를 고친다.
4. 새로운 문제가 생긴다.

새 방식:

1. 먼저 목표 완성 이미지를 만든다.
2. 그 이미지에서 유지할 요소와 버릴 요소를 확정한다.
3. 필요한 에셋을 만든다.
4. 구현자는 재디자인하지 않고 목표 이미지를 구현한다.
5. QA는 빌드 성공이 아니라 목표 이미지 대비 실루엣과 접지감을 본다.

이 방식으로 개선된 부분:

- 책, 탭, 그림자가 한 장면 안에서 조명과 접지감을 공유하게 됐다.
- Shiori 위치/크기를 먼저 후보화하고 선택한 뒤 구현 지시를 줄 수 있게 됐다.
- Claude 프롬프트가 "수정"이 아니라 "확정 목업 구현"으로 바뀌었다.

## 4. 다음 Home 작업 절차

Home을 다시 고칠 때는 아래 순서를 지킨다.

### Step 1. 현재 화면 수정 금지

바로 CSS를 만지지 않는다. 먼저 현재 화면이 목표 목업과 어떻게 다른지 3줄로만
쓴다.

예:

- 책이 밝고 얕아 foreground 중심성이 약하다.
- 하단 탭 그림자가 책상에 붙지 않고 검은 줄처럼 보인다.
- Shiori가 테이프 뒤에 있는 것이 아니라 위에 떠 있는 것처럼 보인다.

### Step 2. 목표 이미지 확정

구현 전에 반드시 하나의 목표 이미지를 정한다. 목표 이미지는 다음을 포함해야 한다.

- 최종 책 크기와 위치
- 최종 책 색감
- 하단 탭 위치와 크기
- 책/탭 접지 그림자
- Shiori 위치, 크기, 자세
- note/CTA/privacy 유무와 위치

목표 이미지가 없으면 Claude에게 구현을 맡기지 않는다.

### Step 3. 에셋 판정

각 에셋을 세 분류로 나눈다.

- Keep: 그대로 쓸 수 있음
- Refit: 색/크롭/alpha/그림자만 보정하면 됨
- Regenerate: 목표 목업에 맞지 않으므로 다시 만들어야 함

판정 기준:

- 가장자리 잔여물 없음
- 색 침범 없음
- 투명 배경이 진짜 alpha인지 확인
- 책상 배경과 광원 방향이 맞음
- 라이브 DOM 텍스트 safe zone이 있음

### Step 4. 그림자는 별도 품질 단계로 본다

그림자는 decorative polish가 아니라 Home의 성공/실패를 가르는 핵심 품질이다.

합격 기준:

- 책 하단과 오른쪽에 접지 그림자가 보인다.
- 그림자는 책 가까이에서 진하고 멀어질수록 흐려진다.
- 하단 탭 각각에도 작은 접지 그림자가 있다.
- 검은 바, 직사각형 판, 분리된 타원처럼 보이지 않는다.
- 책과 탭 그림자의 방향이 같다.

불합격 기준:

- 그림자가 거의 안 보인다.
- 하단에 검은 줄만 보인다.
- 그림자 외곽이 박스처럼 보인다.
- 탭이 공중에 떠 있거나 책 밑에 눌려 사라진다.

### Step 5. 구현 프롬프트는 짧고 확정적으로 쓴다

Claude에게 긴 실패 역사를 전부 주지 않는다. 필요한 것은 다음뿐이다.

- 목표 이미지 경로
- 버릴 구조
- 고정할 레이아웃 수치/관계
- 보존할 기능
- 실패 기준
- QA 범위

금지 표현:

- "살짝"
- "적당히"
- "가능하면"
- "CSS-only면 좋음"
- "현재 구조 유지하면서"

권장 표현:

- "확정 목업 구현"
- "재디자인 금지"
- "이전 shadow 방식 폐기"
- "책+탭+그림자는 하나의 물리적 장면으로 보이게"
- "DOM 텍스트와 클릭 영역은 유지"

## 5. Home 전용 실패 기준

아래 중 하나라도 해당하면 Home 리디자인은 실패로 본다.

- 책보다 배경이 먼저 보인다.
- 책이 밝고 얕아 사진 위 스티커처럼 보인다.
- 하단 탭이 카드 3장처럼 보인다.
- 하단 탭 색이 서로 침범한다.
- 책 주변 털/거스러미/잘린 alpha 잔여물이 보인다.
- 그림자가 검은 바, 박스, 흐릿한 얼룩으로 보인다.
- Shiori가 떠 있거나 테이프/종이 뒤에 숨은 관계가 안 보인다.
- privacy 문구가 CTA나 그림자에 가린다.
- 모바일이 단순 축소판이거나 full-width 버튼 스택이 된다.
- 빌드는 통과했지만 목표 목업과 첫인상이 다르다.

## 6. Claude에게 맡기기 전 체크리스트

- [ ] 목표 목업 1장을 확정했다.
- [ ] Shiori 후보가 확정됐다.
- [ ] 책 색감과 크기 기준이 확정됐다.

## 7. 현재 확정된 Home 방향

현재 기준으로 Home은 다음 방향이 확정에 가깝다.

- 따뜻한 원목 책상 배경
- 짙은 딥 세이지/포레스트 그린 책
- 책 우하단의 은은하지만 식별 가능한 emboss
- 책 하단 오른쪽에 끼워진 3개 탭
- 책과 탭 모두 책상 위에 붙는 자연스러운 접지 그림자
- note 상단 테이프 뒤에서 작은 책을 든 Shiori가 빼꼼 나오는 구성
- live DOM 텍스트/클릭 영역은 별도 유지

## 8. 가장 중요한 교훈

Home 디자인은 "현재 화면을 고쳐서 목표에 가까워지는" 방식으로는 잘 되지 않았다.
반대로 "목표 이미지를 먼저 만들고, 현재 화면을 그 목표에 맞춰 갈아끼우는" 방식에서
처음으로 방향이 좋아졌다.

따라서 다음 Home 작업의 첫 질문은 "어떤 CSS를 고칠까?"가 아니다.

첫 질문은 이것이어야 한다.

> 이 화면은 첫 1초에 진짜 책상 위 물리적 장면으로 보이는가?

그 답이 아니면, QA가 통과해도 디자인은 아직 실패다.
