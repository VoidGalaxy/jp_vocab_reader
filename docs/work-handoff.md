# 클로드·코덱스 공통 작업 인계

기준: 2026-10-07, 제품 코드 `0fb5a0f`. 문서 정리는 `codex/docs-handoff`에서 시작했다. 브랜치 이름과 완료 상태는 스냅샷이므로 현재 Git 상태를 우선한다.

## 작업 전 확인

1. 저장소 루트, 현재 브랜치·HEAD·원격·미커밋 변경을 확인한다. 다른 도구의 변경을 되돌리지 않는다.
2. 적용되는 `AGENTS.md`, 이번 작업에 필요한 스킬의 `SKILL.md`를 읽는다. 로컬 Codex의 스킬 경로가 클로드·클라우드에도 있다고 가정하지 않는다. 없는 스킬은 설치하지 말고 접근 한계를 보고한다.
3. [현재 상태](project-status.md), [로드맵](roadmap.md), [학습 계획 계약](learning-plan.md), 작업 대상의 실제 코드를 읽는다.
4. API·공유 진도는 [공유 lexeme 정책](architecture/shared-lexeme-progress-storage.md), 로컬 DB는 [DB 안전 규칙](operations/database-safety.md)을 확인한다.
5. 승인 목업이 필요한 UI 작업은 전달받은 최신 승인 캡처·계획·에셋 해시를 먼저 확인한다. 구형 v2 문서나 과거 기록을 현재 디자인 권위로 쓰지 않는다.

## 현재 제품 방향

- 독해가 먼저인 일본어 학습 서비스. 한국어 뜻을 기본으로 보여 주며 영어 gloss를 기본 읽기 UI에 추가하지 않는다.
- 깔끔하고 과하지 않은 종이·제본·파일함 세계관. 재질·빛·장식보다 원문·단어·학습 동작이 먼저 읽혀야 한다.
- 홈은 표지/파일 트레이, 읽기는 C 책과 모바일 종이, 복습은 펼친 책, 단어는 파일 서랍/대역 행, 덱은 장부, 계획은 C 패드, 통계는 기록장이다.
- 모바일은 데스크톱 축소판이 아니다. 독립 배치와 읽을 수 있는 글자, 분명한 버튼, 스크롤 소유자를 유지한다.
- 승인 없이 이미 완료한 화면을 다시 보정하지 않는다. 실제 결함 또는 새 요구가 있으면 범위를 먼저 정한다.

## 설계·구현 흐름

- 진단 → 다른 방향 시안 → 사용자의 방향 선택 → 보정·최종 승인 → 글자 없는 에셋/안전영역 → 구현 → 실제 데이터 검증 → 최종 승인 순서다.
- 배경 재질·공유 빛·그림자는 이미지, 단어·수치·날짜·상태·버튼·클릭 영역은 살아 있는 DOM이다.
- Gate A는 시안·계약, B는 화면 구현, C는 실제 데이터, D는 경계·접근성·회귀, E는 정리·최종 검증이다. 계약에 따라 C-0/C-1처럼 나눌 수 있다.
- 첫 작업 지시는 대상과 목표 중심으로 짧게 쓴다. 광범위한 QA와 최종 보고는 최종 후보 단계에서 수행한다.
- UI 변경은 1280/390에서 첫인상을 확인하고 최종 후보에서 1024/800/375/320 등 위험 폭을 확장한다. 빌드 통과를 브라우저·시각 승인으로 대체하지 않는다.
- 기능 안정화는 재현 → 최소 수정 → 회귀 검사 순서다. 미검증을 통과로 보고하지 않는다.

## 변경·데이터 경계

- 기존 콜백·CRUD·공유·인증·API·저장 키·SRS·스키마를 보존한다. 새 데이터 계약이나 이력 이전은 별도 승인한다.
- 로컬에서 Neon/운영 DB 접근 금지. 실행할 때 세션 전용 SQLite를 명시한다. 기존 `.env`의 연결을 신뢰하지 않는다.
- 원문 전체의 서버 보관 기능을 추가하지 않는다. 분석 요청과 저장 예문은 별개임을 설명한다. 공유 패키지에 개인 이력이나 원문 전체를 넣지 않는다.
- 계정 경계에서는 조회 결과와 복습 세션을 분리한다. 옛 응답이 새 계정 화면이나 새 세션을 덮지 않아야 한다.
- 읽기 세션은 아직 기기 공통 저장이다. 임의 삭제·계정 키 이전을 하지 않는다.
- `.env`, 토큰, DB, 대량 사전/데이터, `.next`, `node_modules`, `tsconfig.tsbuildinfo`, QA 사본·스크래치는 커밋하지 않는다.
- 미추적 `references/`와 이미지에는 사용자 원본이 있다. 삭제·일괄 등록·자동 정리 금지. 필요한 인계 파일만 선별한다.

## 검증 명령

프론트: `.nvmrc` 기준 Node 24, 테스트 최소 Node 22.18. 이미 설치된 의존성을 사용하며 lockfile 변경을 검증 작업에 섞지 않는다.

```powershell
cd frontend
npm test
npm run typecheck
npm run build
```

백엔드: 현재 환경에서 PostgreSQL 선택 변수를 제거하고 임시 SQLite만 사용한다. 경로는 저장소 루트에서 시작한다.

```powershell
cd backend
Remove-Item Env:LEARNING_PLAN_TEST_POSTGRES_URL -ErrorAction SilentlyContinue
$env:DATABASE_URL = "sqlite:///./qa_handoff_session.db"
$env:APP_ENV = "development"
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe tests/test_learning_plan_progress.py
.\.venv\Scripts\python.exe scripts/check_shared_deck_srs_regression.py
```

테스트는 자체 임시 DB로 연결을 덮어쓰며 고정 임시 파일 이름을 사용한다. 같은 테스트를 병렬 실행하지 않는다. 최종 단계에서 `git diff --check`를 확인하고 자신이 만든 서버·임시 DB만 정리한다. 빌드는 같은 폴더의 dev 서버와 동시에 돌리지 않는다. Windows 실행 제한 오류와 제품 실패를 구분하며 우회에는 해당 도구의 승인이 필요하다.

### PostgreSQL 비교

- 실제 서버 검증은 미완료다. 설치·컨테이너 준비는 먼저 승인받는다. 운영 연결이나 일반 `DATABASE_URL`을 테스트 대상으로 재사용하지 않는다.
- 새 빈 로컬 DB 이름은 `jp_vocab_test` 또는 `jp_vocab_test_<소문자 영숫자>` 계열이다. 명시적 loopback 주소와 보호 검사 조건을 모두 충족해야 한다.
- `LEARNING_PLAN_TEST_POSTGRES_URL`을 설정한 뒤 `tests/test_learning_plan_progress.py`를 **직접 실행**한다. 이 모드는 discovery를 지원하지 않는다.
- URL 검사는 연결 전에, 빈 DB 검사는 읽기 전용으로 수행한다. 확인 실패·설정 덮어쓰기에는 초기화·쓰기를 하지 않는다. URL·비밀번호는 보고서에 출력하지 않는다.
- 실행 후 테이블이 남는다. 같은 DB를 지우거나 재사용하지 말고 다음 실행에는 새 빈 DB를 준비한다. 이 검사에는 객체 검사 범위와 검사 이후 경쟁 조건의 한계가 있으므로 독점 테스트 DB가 필요하다.

## 역할·종료 보고

- 클로드는 승인 범위의 구현·검증 후 멈춘다. 스테이징·커밋·푸시·병합·브랜치 삭제를 하지 않는다.
- 코덱스는 검토와 릴리스 관리를 맡는다. 사용자 승인 없는 Git 릴리스를 하지 않는다.
- 승인된 릴리스 순서는 범위별 등록 → 검토 → 커밋 → 작업 브랜치 푸시 → main 병합·푸시 → 확인 → 로컬/원격 작업 브랜치 삭제다. 사용자 원본은 보존한다.
- 종료 보고에는 변경 파일, 확인한 동작·테스트 수, 실제/모킹 데이터 구분, 미검증·남은 위험, 서버·DB 정리 여부, 다음 승인 지점을 짧게 적는다.
- 클라우드에는 현재 대화나 미추적 로컬 자료가 자동 전달되지 않는다. 이 문서와 필요한 최신 계약·승인 캡처를 보내고, 해당 코드가 원격에 있는지 확인한다.
