# Gate D-2 U10 구현 계획 (U10-0, 승인 대기)

계약: `U10_CONTRACT.md`(승인 항목 A1~A10). 아래 단위는 승인 뒤에 진행한다. 이 계획을 쓰는 동안 제품 코드·스키마·자료는 바꾸지 않았다. **PostgreSQL은 미검증·출시 차단이다**(설치·원격 접속으로 우회하지 않음).

## 1. 단위와 의존 순서

```
U10-c0 증명 보존 기준 테스트 ─> U10-a 내용 최소화(새 쓰기 + 삭제 경로) ─> U10-b 기존 자료 최소화 도구
                                                              └─> U10-d 롤백 기간(논리 만료) ─> U10-e 기간 뒤 R 필드 정리 도구
```

| 단위 | 묶음 | 승인 | 내용 | 파일 |
| --- | --- | --- | --- | --- |
| U10-c0 | 증명 보존 | A2·A7 | 변경 전 기준 고정: 복원 증명, B안 허가, `_was_converted`, ID 참조, 롤백 결과를 형식 1에서 기록한 회귀 테스트 | 테스트 |
| U10-a | 내용 최소화 | A1·A8·A10 | apply·rollback 쓰기를 형식 2로, 읽기는 형식 1·2 모두. 롤백 필수 필드 검증(결함 보정). 카드·덱 삭제 트랜잭션에서 해당 카드 snapshot의 C 필드 제거(원값 CAS) | `migration.py`, `identity.py`(형식 2 읽기), `vocab_repository.py`, `deck_repository.py`, 테스트 |
| U10-b | 내용 최소화 | A1 | 기존 형식 1 → 2 일회성 도구(dry-run 기본, 계정 확인, CAS, 배치·재개, 손상 보고) | `scripts/`, 테스트 |
| U10-d | 만료·정리 | A3·A4·A5·A6 | `rollback_plan`이 실행별 기간을 계산해 닫힌 실행을 거부. 상태 값은 바꾸지 않음 | `migration.py`, 테스트 |
| U10-e | 만료·정리 | A2 | 기간이 지난 apply 실행의 R 필드만 제거(L·P와 미사용 허가는 보존, 행은 지우지 않음) | `scripts/`, 테스트 |

- 증명 보존(U10-c0)을 먼저 하는 이유: a·b·e가 모두 같은 행을 줄인다. 줄이기 전과 후에 증명·허가·롤백 결과가 같다는 기준이 먼저 있어야 한다.

## 4. 경합 검증 계획 (실제 스레드 두 개, 계정 쓰기 잠금 순서 기록)
- 정리 도구(U10-b·e) ↔ 평가(복원 카드·B안 첫 평가): 양쪽 순서에서 증명·허가가 성립하고, 로그·교체 기록이 각각 한 번만 생긴다.
- 정리 ↔ 롤백, 정리 ↔ 재전환: 정리가 먼저면 롤백·재전환은 형식 2를 읽는다. 롤백이 먼저면 정리가 원값 CAS로 충돌을 보고하고 덮어쓰지 않는다.
- 정리 ↔ 카드 삭제: 어느 순서든 C 필드가 없고 L 필드가 남는다.
- 기간 경계 ↔ 롤백 호출: 서버 시각을 고정한 정각 전후.
- 모두 스레드 종료, 각 작업의 값·예외, 최종 카드·로그·snapshot·실행·교체 기록 수를 대조한다.
