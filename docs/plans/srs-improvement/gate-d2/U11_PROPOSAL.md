# U11 승인 요청: 완료 기준 V3 서버 판정과 최초 완료 출처 보존 (2026-10-17)

제품 코드는 바꾸지 않았다. 아래 두 가지가 승인되면 계약·버전별 처리표를 먼저 고정하고 구현한다.

## 1. 승인 상태
- `APPROVAL_REQUEST.md` D-C1(V3, 새 버전 `meaning-completion-v1`, draft 판정·`first_completed_at`은 출처 버전과 함께 보존)과 D-C3(서버 판정만, 화면 노출 없음)은 권장안으로 적혀 있다.
- 같은 문서 5절(2026-10-11)은 "완료 기준 V3는 **후속 단위의 기준으로만 기록**(이번에 구현하거나 기존 자료에 적용하지 않음)"이다. 구현 승인 기록은 찾지 못했다.
- 그래서 **V3 기준과 "서버 판정만" 범위의 구현 승인**이 필요하다.
  - V3 기준: Review 상태, S ≥ 30일, 마지막 Again 이후 성공(hard·good·easy) 서울 날짜 3개 이상, 그중 직전 실제 평가와 UTC 7×24시간 이상 떨어진 성공 2회 이상.
  - 새 실제 평가부터만 판정한다. 조회·앱 시작·도구로 재판정하거나 백필하지 않는다. 화면 노출은 없다(D-C2 유지).

## 2. 구조상 문제: 지금 열로는 출처를 지킬 수 없다
- 카드 열 `completion_metric_version`은 FSRS 평가마다 **현재 판정 버전으로 덮어쓰인다**(`reviews.py` 208행). `first_completed_at`은 처음 값이 유지된다.
- V3를 그대로 넣으면 draft로 생긴 최초 완료 카드의 열이 다음 평가에서 `meaning-completion-v1`로 바뀐다. 결과적으로 draft 완료가 V3 완료처럼 보인다(출처가 섞임).
- 전환(`apply_plan`)도 legacy 이력을 재생해 `first_completed_at`을 만들고 열에 현재 버전을 쓴다(`migration.py` 161~171행). V3에서는 이것이 legacy 이력으로부터의 소급 완료가 된다.
- 롤백은 카드의 완료 값을 그대로 둔다(`card or before`). 재시도는 저장된 영수증 응답을 그대로 돌려준다. 두 경로는 바꿀 필요가 없다.

## 3. 제안 (권장 A, 스키마 변경 없음)

| 항목 | A(권장): 열의 뜻을 "최초 완료의 출처"로 고정 | B: 출처 전용 새 열 추가 |
| --- | --- | --- |
| 스키마 | 없음 | 카드 두 표에 열 추가(SQLite·PG 이전 필요, PG는 미검증) |
| 카드 `completion_metric_version` | `first_completed_at`을 **처음 쓸 때만** 그 판정 버전을 같이 쓰고, 이후 평가는 두 값을 건드리지 않음 | 현재처럼 현재 버전 |
| 현재 판정 버전 | 평가 응답·영수증의 `completion_metric_version`·`completion_status`(카드에 저장하지 않음, 지금과 같음) | 같음 |
| draft 최초 완료가 있는 카드가 나중에 V3 완료 | 최초 완료 시각·출처는 draft 그대로. **V3 최초 완료 시각은 따로 남지 않음** | V3 최초 완료를 별도 열에 기록 가능 |

- 기존 자료(A): 백필·일괄 수정 없음.
  - `first_completed_at`이 있고 열이 `…-v1-draft`인 카드는 출처 draft로 읽는다. 지금까지 실행된 판정은 draft뿐이라 추정이 아니다.
  - `first_completed_at`이 있는데 열이 NULL이거나 알 수 없는 값이면 **출처 확인 불가**로 읽고 고치지 않는다.
  - `first_completed_at`이 NULL이면 열 값은 의미가 없다(기존 `…-v1-draft` 값이 남아 있어도 출처로 쓰지 않음).
- `needs_relearning`(응답 내부 값, 화면 미노출): **출처가 현재 판정 버전과 같은 최초 완료**가 있을 때만 계산한다. draft 출처 최초 완료는 이력으로만 남기고 V3 현재 판정과 섞지 않는다.
- 전환: legacy 이력 재생으로 **새 V3 최초 완료를 만들지 않는다**. 카드에 이미 있는 최초 완료·출처는 그대로 둔다. 전환 뒤 첫 실제 평가부터 V3로 판정한다.
- 롤백·재전환·U10 정리 도구·영수증·원로그·snapshot: 완료 값과 출처를 덮어쓰거나 새 완료를 만들지 않는다(지금 동작 유지, 테스트로 고정).

## 4. 결정해 주실 것
1. **V3 서버 판정 구현 승인**(위 기준, 서버 판정만, 화면 노출 없음, 새 평가부터).
2. **출처 보존 방식**: A(권장, 스키마 없음, draft 최초 완료가 있는 카드의 V3 최초 완료 시각은 남지 않음) 또는 B(새 열, 스키마 변경).
   - A를 고르면 3절의 `needs_relearning`·전환 규칙도 함께 승인으로 본다.
