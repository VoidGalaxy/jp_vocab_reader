# 식별 불가 개인 카드의 평가 쓰기 차단 — 계약안 (2026-10-17, 승인 대기)

제품 코드는 바꾸지 않았다. 아래는 승인 뒤 구현할 계약안이다.

## 1. 재현 (세션 전용 합성 SQLite, 실제 탐지·표시 경로)
- FSRS 계정의 legacy 개인 카드에 카드 생성보다 앞선 로그가 있다. `identity.scan_identity`가 이를 `log_before_created`로 찾았고, `identity.flag_identity_unknown`이 표시했다(1건).
- 막혀 있는 곳: 전환 dry run은 `identity_unknown`, 학습 큐는 제공하지 않는다.
- 막히지 않는 곳:
  - FSRS 계정 클라이언트 형식(`request_id`·`expected_card_version` 일치)의 `POST /study-items/{id}/review` → **200**. legacy 평가로 기록됐다: 로그 +1, 카드 버전 0→1, 정답 수 2→3, 엔진 legacy 그대로.
  - legacy 모드 계정의 legacy 형식(`rating`만) → **200**. 로그가 하나 더 쌓였다.
- 원인: `vocab_repository.record_review`의 legacy 분기는 식별 불가 표시를 보지 않는다. 표시 확인은 FSRS 분기(`reviews.record_fsrs_review`)에만 있다.

## 2. 권장 규칙
**식별 불가로 표시된 개인 카드만, 엔진·계정 모드와 관계없이 새 평가 쓰기를 409 `card_identity_unknown`으로 거부한다.**

| 대상 | 처리 |
| --- | --- |
| `srs_card_identity_flags`에 있는 개인 카드(legacy·FSRS 엔진, legacy·FSRS 계정 모드 모두) | 새 평가 쓰기 409 `card_identity_unknown`, 쓰기 0 |
| 표시 없는 정상 legacy 카드, 일반 미전환 카드 | 대상 아님(지금과 같음) |
| 구독 단어(진도 행) | 대상 아님. 표시는 개인 카드만 있음 |
| 평가가 아닌 쓰기(내용 수정, 삭제 등) | 이번 계약 범위 밖(지금과 같음). 확정 삭제는 계속 가능 |

- 오류 코드는 기존 `card_identity_unknown`(FSRS 분기에서 이미 쓰는 코드, 409)을 그대로 쓴다. 새 오류 코드는 없다.
- 원로그를 고치거나 지우지 않고, 표시를 자동으로 풀지 않는다. 표시 해제 경로는 지금처럼 없다(별도 승인 항목).

## 3. 판정 순서 (`record_review`, 두 분기 공통 앞단)
1. 계정 쓰기 잠금(`begin_card_write`) — 지금과 같음.
2. 권한·존재 확인: 이 계정의 카드가 아니거나 없으면 404(지금과 같음). 존재를 알려 주지 않는다.
3. 영수증 확인(`find_receipt`, `request_id`가 있을 때만) — 지금 규칙 그대로:
   - 표시 **이전**에 쓰인 영수증은 재생하지 않는다(`identity.receipt_may_be_other_card` → `card_version_conflict`, 쓰기 0).
   - 표시 **이후** 영수증은 이 규칙이 생기면 새로 생길 수 없다. 이미 있다면 지금처럼 재생된다.
4. 격리 확인: 표시가 있으면 409 `card_identity_unknown`, 엔진·쓰기 전에 끝낸다.
5. 그 뒤 기존 FSRS·legacy 분기.
- FSRS 분기의 지금 순서(영수증 → 격리)와 같다. legacy 분기에 4를 추가하는 것뿐이다.

## 4. 기존 성공 요청의 재시도
- `request_id`가 있는 요청이 표시 전에 성공했다면, 재시도는 3의 규칙대로 `card_version_conflict`(쓰기 0)다. 저장된 응답을 다른 카드일 수 있는 지금 카드에 재생하지 않는다(U3 규칙 유지).
- `request_id`가 없는 legacy 요청은 재시도를 구별할 수 없다. 표시 뒤의 요청은 모두 새 쓰기로 보고 409로 거부한다. 응답을 잃은 뒤의 재시도도 409지만, 중복 기록은 생기지 않는다.

## 5. 표시와 평가의 잠금 순서
- 표시(`flag_identity_unknown`)와 평가는 같은 계정 쓰기 잠금을 잡는다. SQLite는 BEGIN IMMEDIATE, PostgreSQL은 사용자 행 `FOR UPDATE`다.
- 평가는 잠금을 얻은 뒤 표시를 읽는다.
  - 표시 → 평가 순: 평가가 409.
  - 평가 → 표시 순: 평가는 이미 커밋됐고, 표시가 뒤에 붙는다. 그 로그는 지우지 않는다.
- 같은 잠금이라 둘이 겹쳐도 중간 상태를 보지 않는다. PostgreSQL 경로는 미검증이다(출시 차단).

## 6. 승인 뒤 검사표
- 재현 두 경로(FSRS 계정 형식, legacy 모드 형식) → 409, 전체 표 동일.
- 정상 legacy 카드·미전환 카드·구독 단어 → 지금과 같은 결과.
- 표시 전 성공 요청의 재시도 → `card_version_conflict`, 쓰기 0. 다른 계정 카드 → 404.
- 표시와 평가를 실제로 겹쳐 두 순서 모두(LockProbe).
- 큐·전환 결과 불변, 원로그 불변, 표시 불변.

## 7. 승인 기록 (2026-10-18)
- 사용자가 2절 권장안을 승인했다: 식별 불가로 표시된 개인 카드는 엔진·계정 모드와 관계없이 새 평가 쓰기를 409 `card_identity_unknown`으로 거부한다.
- 대상 아님: 정상 legacy 카드, 일반 미전환 카드, 구독 단어. 내용 수정·확정 삭제는 기존대로다.
- 금지: 원로그 수정·삭제, 표시 자동 해제, 새 오류 코드.
- 구현 위치: 개인 평가 공통 앞단(`vocab_repository.record_review`).
  - 순서: 계정 쓰기 잠금 → 소유권·존재(없으면 기존 404, 표시 여부 미노출) → 기존 영수증 검사(재생·만료·충돌·표시 이전 영수증 거부 규칙 그대로) → 식별 불가 409 → 기존 엔진 분기.
