# Gate D-2 구현·검증 계획 (승인 전)

작성: 2026-10-11. 결정은 `APPROVAL_REQUEST.md`(이하 AR). 이 문서는 계획만 담는다. **제품 코드·스키마·의존성 변경 없음.**
각 단위는 적힌 승인을 받은 뒤 시작하고, 끝나면 보고 후 멈춘다(작은 검토 단위). 승인되지 않은 결정에 기대는 단위는 시작하지 않는다.

## 0. 공통 규칙

- 앱·DB import 전에 `APP_ENV=test`와 세션 전용 SQLite `DATABASE_URL`을 지정하고 확인한다. 운영·Neon·기존 DB에 접근하지 않는다.
- FSRS는 합성 계정에만 켠다. 실제 사용자 이전·기본 FSRS 활성화 없음.
- 금지(모든 단위): 원로그 삭제·수정, 추정 재연결, 중복 제거, 과거 날짜 추정·로그 합성, legacy 레벨→안정도 환산, 삭제 카드 복구, 신규 실적 재소비, 실패·확인 불가를 0으로 표시.
- D-1에서 확정한 지표·홈 범위·단어장 필터·갱신 동작은 바꾸지 않는다. 큐 분류가 바뀌면 그 화면 수치는 `classify()` 공유로 따라온다(회귀 확인만).
- 모든 단위의 공통 회귀: 백엔드 전체(PG 건너뜀은 미검증으로 기록), 기존 회귀 스크립트 9종, 프론트 `npm test`·typecheck, `git diff --check`. 빌드는 D-2 마지막에 서버를 멈춘 뒤 1회.
- 공통 중단 조건: 위 금지 사항이 필요해짐, 승인 범위를 넘는 스키마 변경, legacy 계정의 요청·값 변화, 원로그 지문 변화, 기존 `-v1-draft` 완료 이력 변화, PostgreSQL을 설치·원격으로 검증해야만 진행되는 상황.

## 1. 의존 관계

```
U1 참조 조사 ─> U2 id 재구성 ─> U3 원장·식별 불가 ─┬─> U4 학습 이력 상태 ─> U5 전환 ─> U6 큐 ─> U7 첫 평가·증거 구간 ─> U8 롤백·재전환 ─> U10 snapshot 최소화
                                                    └─> U9 영수증
U7 ─> U11 완료 기준(서버 판정만)
U5~U11 ─> U12 합성 리허설
E: PostgreSQL(D-P1·D-P5, 출시 차단)
```

카드 정체성이 유일해야 이력·영수증·snapshot 검사가 의미가 있으므로 U1~U3이 먼저다.

## 2. 구현 단위

### U1. 카드 id 참조 조사(읽기 전용)
- 승인: D-P2a
- 파일: `backend/app/srs/identity.py`(신규, 읽기 전용 함수), `backend/tests/test_srs_d2_identity.py`(신규)
- 내용: 서버 쪽 개인 카드 id 참조의 최대값 계산(AR X10의 목록). `meaning_feedback.vocabulary_id`의 의미를 코드로 확인해 포함 여부를 보고.
- 테스트: 최대 id 카드를 지우고 그 id가 로그·영수증·snapshot·실행 범위에만 남은 경우 계산값 ≥ 그 id. 쓰기 0.
- 중단: 서버 밖(브라우저 저장소 등)에만 남은 참조가 정합성에 필요한 경우 → 보고.

### U2. SQLite 개인 카드 id 재사용 방지
- 승인: D-P2a
- 파일: `backend/app/database.py`(SQLite 초기화·재구성 단계), U1 함수, 테스트
- 내용: `vocab_items`를 AUTOINCREMENT로 재구성(행·id·내용·인덱스 보존, 한 트랜잭션, 실패 시 원상). 시퀀스 = U1 최대값. 재실행 멱등. PG 코드 경로는 손대지 않음.
- 테스트: **삭제된 최대 id와 남은 로그·영수증·snapshot**: 재구성 뒤 새 카드 id가 어떤 기존 참조와도 겹치지 않음, 새 카드의 첫 평가 정상(F9 막힘 없음). 단어 삭제·덱 삭제 두 경로. 재구성 중 실패 주입 → 원상. 재구성 전후 행 수·내용 해시 동일.
- 중단: 재구성이 다른 테이블의 FK·트리거를 바꿔야 할 때, 행 수·내용 해시가 달라질 때.

### U3. 삭제 원장과 식별 불가 처리
- 승인: D-P2c, D-P6a, D-P6b, D-P6c
- 파일: 스키마(원장 테이블, 식별 불가 표시), 삭제 경로(`vocab_repository.py`, `deck_repository.py`, `database.py` 삭제 함수), `goals.py`(날짜 한정 규칙), `reviews.py`(옛 영수증 거부), `migration.py`(전환 차단·롤백 건너뜀)
- 내용: 삭제 때 내용 없는 원장 기록. 혼합 의심 신호로 식별 불가 표시(재연결·삭제 없음).
- 테스트:
  - **옛 요청 재시도와 새 카드 식별 충돌**: 재구성 전 이미 혼합된 id에서 삭제 카드의 옛 request_id를 새 카드 URL로 재시도 → 옛 응답·내용이 나오지 않음(409), 평가 추가 0.
  - **손상 시각과 식별 불가**: 식별 불가 id의 로그 시각이 모두 읽힘 → 그 로그가 있는 서울 날짜만 확인 불가, 오늘 신규 학습 계속. 시각 하나라도 손상 → 계정 전체 확인 불가(날짜 한정 미적용).
  - 탐지 신호가 없는 혼합(같은 초 재사용 등)은 탐지되지 않음을 테스트로 고정하고 잔여 위험으로 보고(전부 탐지 보장 금지).
  - 로그 수·내용 해시 불변, 오늘 평가 횟수·기록 달력은 로그 행 수 그대로.
- 중단: 식별 판정을 위해 로그를 옮기거나 지워야 할 때.

### U4. 학습 이력 상태(로그 0건 과거 학습)
- 승인: D-H7
- 파일: 스키마(카드 열 2개, `srs_` 접두어 밖 또는 롤백 제외 명시), `goals.py`, `migration.py`(기록 시점), 테스트
- 내용: 전환 때 `logged`/`before_tracking`/`unknown`과 기준일을 한 번 기록. 신규 집계 규칙(C 3-3).
- 테스트: TEST_MATRIX I11(C1~C7): 기준일 이후 제외(exact), 당일·이전 확인 불가(하한 유지), 기준 시각 손상은 모든 날짜 확인 불가. 이후 로그를 첫 평가로 보지 않음.
- 중단: 기준일을 좁히기 위해 생성 시각 등 승인되지 않은 증거가 필요해질 때.

### U5. 불완전 이력 전환
- 승인: D-H1(D-H6 유지 확인)
- 파일: `migration.py`, 테스트
- 내용: 불완전 후보를 승인 값으로 전환. 손상 시각·식별 불가는 차단 유지.
- 테스트:
  - **이전 중 실제 평가**: 미리보기와 적용 사이 평가·편집·삭제·구독 해제 → 해당 카드 `conflict`, 복구 없음.
  - **중간 실패, 중단·재개**: 배치 중 예외 주입 → 실행 `failed`, 커밋된 카드만 snapshot·커서 반영, 재개 시 다음 카드부터, 이미 적용한 카드 재적용 0.
  - 누락·순서 불명·카드값 불일치 각각 승인 값으로 전환, 로그·seen·분류·예약 보존(I1).
- 중단: 전환이 원로그·카운터를 바꿔야 할 때.

### U6. 큐 출제
- 승인: D-H2
- 파일: `queue.py`(`classify`), 테스트
- 내용: 승인된 전환이 `incomplete`로 표시한 상태 없음 카드를 effective due에 장기 복습 버킷으로. 새 FSRS 카드가 남의 로그를 가진 경우는 `blocked_history` 유지.
- 테스트: 신규가 아님(오늘 새 단어 미소비), effective due 전 `pending_later`, 홈·통계·단어장 지금 복습 수가 큐와 일치(D-1 회귀), 재사용 카드 미출제.

### U7. 첫 실제 FSRS 평가와 증거 구간
- 승인: D-H3, D-H4, D-H8
- 파일: `reviews.py`, `completion.py`, 스키마(증거 경계), 테스트
- 내용: F9 차단 해제는 승인 대상 카드에만. 증거 경계 기록.

### U8. 롤백·재전환
- 승인: D-H5
- 파일: `migration.py`, 테스트
- 테스트:
  - **이후 평가를 보존하는 롤백**: 전환 → 평가 2회 → 롤백 → 로그 수·내용 불변, legacy 예약은 이후 평가로 재계산, 완료 이력 보존, 학습 이력 상태·증거 경계 보존(K5).
  - **로그 0건 과거 학습 카드의 전환·첫 평가·롤백·재전환**(C 3-4 사례 B, I10): 각 단계 오늘 새 단어 제외, 표시 유지, 날짜 추정·합성 로그 없음, seen 1.
  - 삭제·권한 상실 카드는 롤백·재전환 모두 건너뜀(복구 없음).
  - 롤백 뒤 재전환을 두 번 반복해도 결과 동일(D-H5 권장안 기준).

### U9. 영수증
- 승인: D-P3a, D-P3b, D-P3d(만료 처리는 D-P3c 값 승인 뒤)
- 파일: `reviews.py`, 일회성 정리 스크립트(`backend/scripts/`), 테스트
- 테스트:
  - 첫 평가와 같은 요청 재시도 응답이 바이트 단위로 같고 카드 내용 필드 없음, 그사이 뜻을 바꿔도 불변(P9). 프론트 회차가 그대로 동작(브라우저).

  - **삭제·권한 상실 뒤 재시도**: 404, 내용 노출 없음(P6).
- 중단: 응답 축소로 프론트 회차 동작이 바뀔 때(그때는 보고 후 멈춤).
