## 3. 승인 후 첫 구현 범위(권장)

묶음 2의 D-P2a·D-P2c(재사용 방지와 삭제 원장, `PLAN.md` U1~U3)를 가장 먼저 한다. 다른 모든 묶음의 테스트가 "카드 정체성이 유일하다"는 전제 위에 있기 때문이다. 이 단위는 화면 동작을 바꾸지 않고, 불완전 이력 전환(묶음 1)이나 보존 기간(묶음 3) 값 없이도 진행할 수 있다.

## 4. 미검증·차단

- PostgreSQL: 실제 검증 전까지 출시 차단. 설치·원격 DB로 우회하지 않는다.
- 실제 사용자 자료의 불완전 이력 분포와 완료 기준 타당성: 합성 자료만 있음.
- `meaning_feedback.vocabulary_id`가 개인 카드 id인지: U1에서 코드로 확인 전까지 시작값 계산에 포함하는 쪽으로 둔다.

## 5. 승인 기록과 계약 보완 (2026-10-11, U1~U3 진행 지시)

- 이번 지시로 진행하는 것: **U1~U3**(개인 카드 ID 참조 조사, SQLite ID 재사용 방지, 삭제 원장·식별 불가). U4 이후는 진행하지 않는다.
- 후속 단위의 기준으로만 기록(이번에 구현하거나 기존 자료에 적용하지 않음): 영수증 보존 7일(D-P3c), 롤백 가능 기간 30일(D-P4b), 완료 기준 V3는 서버 판정만 하고 화면에는 노출하지 않음(D-C1·D-C3).

계약 문구 보완(구현은 이번 범위 밖):

1. **D-H1 "완료 이력 없음"의 뜻**: 불완전 이력 전환이 **새 완료 증거를 만들어 내지 않는다**는 뜻이다. 카드에 이미 있는 `first_completed_at`·`completion_metric_version`(최초 완료 기록)은 지우거나 NULL로 바꾸지 않는다. 지금 롤백도 카드의 완료 기록을 남긴다(`migration.py:306~307`).
2. **D-H5 재전환 snapshot 복원의 조건**: 다음이 모두 참일 때만 snapshot의 FSRS 상태를 복원한다.
   - 카드가 존재하고 현재 권한이 있으며, 식별자가 유효하다(식별 불가 표시가 없고, 삭제 원장 기록 뒤 다시 생긴 같은 id가 아님).
   - snapshot이 있고 만료·삭제되지 않았다.
   - 정해진 비교 기준에서 변경이 없다: 롤백 이후 카드 버전·카드 지문, 로그 지문(새 로그 없음), 엔진 설정 버전이 롤백 직후와 같다.
   - 만료·삭제된 snapshot을 되살리지 않는다. 조건이 맞지 않는다고 불완전 이력을 임의로 전체 재생해 상태를 만들지 않는다.
   - snapshot이 없을 때의 대체 처리(예: 상태 없음으로 전환, 또는 재전환 차단)는 **U8 시작 전에 명시하고 승인받는다.**
