# 책갈피 SRS 제품 설계안

작성: 2026-10-08. 현 구조 기준: main `e2c07f8` 및 `AUDIT_AND_RESEARCH.md`.
상태: **제안 v0.2, 구현 전**. 표시 용어는 사용자 요청에 따라 '학습 완료'로 확정했다. 수치/이전/신규 상한 계약은 승인 전이다. 제품 코드, API, 스키마, 기존 계획 계약은 변경하지 않았다.

코드 교체 계획은 `REPLACEMENT_PLAN.md`, 데이터/실행 계약 초안은 `IMPLEMENTATION_CONTRACT.md`, 첫 작업 지시는 `CLAUDE_GATE_A_PROMPT.md`를 따른다. '학습 완료'는 주요 의미 학습 목표 달성을 뜻하며, 영구 암기나 유지 복습 종료가 아니다.

## 1. 목표와 설계 경계

목표는 원문에서 만난 단어의 핵심 뜻을 떠올리고, 실제 시간 간격을 두어 그 기억을 안정시키는 것이다.
첫 버전은 일본어 표제어 → 핵심 한국어 의미 인출이다. 한자 읽기, 역방향 생성, 모든 뜻, 문장 활용까지 완료했다고 주장하지 않는다.
문맥 예문은 정답 뒤 이해를 돕는 자료다. 읽기 화면에서 뜻/예문을 본 행동은 시험을 통과한 행동이 아니다.

FSRS는 검증된 기억 계산 엔진으로 유지한다. 우리 제품은 학습 참여, 출제 큐, 하루량, 진도, 계획, 안전한 기록을 설계한다.
읽기 분류에 따라 FSRS 안정도를 임의 가산하거나, 정답 횟수만으로 간격을 곱하는 독자 공식을 만들지 않는다.

```text
원문에서 단어 발견
  -> 뜻/문맥 확인 + 읽기 자기분류
  -> 저장한 단어 / 선택한 덱의 미학습 단어
  -> 오늘 도입할 신규량에 맞춰 첫 인출
  -> 4종 평가 -> FSRS 기억 상태/다음 시각 계산
  -> 짧은 학습/재학습 + 장기 복습
  -> 학습 완료 진도 + 유지 복습
  -> 다시 원문 읽기
```

## 2. 서로 다른 세 축

| 축 | 값 | 결정하는 것 |
| --- | --- | --- |
| 읽기 자기분류 | 아는 / 헷갈림 / 모름 / 미분류 | 읽기 강조, 검색/정리. FSRS 상태를 직접 변경하지 않음 |
| 복습 참여 | 미도입 대상 / 참여 중 / 보류 | 신규 도입 또는 복습 대상으로 삼을지 |
| 기억/학습 상태 | 미학습 / 학습 중 / 복습 / 재학습 + 학습 완료 지표 | FSRS의 단계와 실제 학습 이력 |

- 단어를 보는 것, 뜻을 여는 것, 분류만 하는 것은 평가 로그를 만들지 않는다.
- 원문에서 unknown/uncertain 저장을 하면 미학습 대상이 된다. known을 명시적으로 저장한 단어도 미평가 대상이며, 첫 평가 없이 학습 완료로 취급하지 않는다.
- 저장하지 않은 known 표시만으로 개인 SRS 카드를 새로 만들지 않는다.
- 구독 덱을 선택해 학습하면 미평가 단어를 분류 4종과 무관하게 도입 후보로 삼는다. 전 덱을 구독한 순간 모든 단어를 당일 복습으로 밀어 넣지 않는다.
- 평가 Easy도 복습 참여를 종료하지 않는다. 자기분류를 자동으로 known으로 바꾸지 않는다.
- 복습에서 빼고 싶으면 별도 보류를 명시적으로 고른다. 보류는 카드/이력 삭제가 아니며 되돌릴 수 있다.
- 보류된 단어는 덱에서 없어지거나 학습 완료로 세지 않는다. 전체 N개 중 보류 M개를 별도로 알리고, 덱 전체 학습 목표가 남았음을 유지한다.

위 정책은 기존 known 제외 정책과 다른 **새 계약**이다. 이전 known의 자동 재참여는 아래 이전 절차와 별도로 승인해야 한다.

## 3. 학습 상태와 평가

| 화면 상태 | 의미 | 이동 |
| --- | --- | --- |
| 미학습 | 유효한 첫 평가 없음 | 첫 평가를 하면 라이브러리 규칙에 따라 학습/복습으로 진입 |
| 학습 중 | 짧은 단계에서 초기 기억을 형성 중 | 단계 완료 시 복습. Easy의 단계 건너뛰기는 고정한 라이브러리 동작을 따름 |
| 복습 | 장기 간격으로 기억을 유지 중 | 성공 시 상태/간격 갱신. 실패 시 설정한 재학습 단계 |
| 재학습 | 이전 복습 카드에서 기억 실패 | 짧게 다시 익힌 뒤 장기 복습으로 복귀 |
| 학습 완료 | 아래 제품 기준을 충족한 복습 카드의 표시 | FSRS의 종결 단계가 아님. 실패하면 재학습 필요로 표시하고 유지 복습은 계속됨 |

미학습과 보류는 제품의 참여/첫 평가 판정이고, Learning/Review/Relearning 전이는 FSRS 구현을 따른다.
모든 신규가 반드시 같은 단계/간격을 거친다고 가정하지 않는다.

평가 의미:

- 다시: 정답을 보지 않고는 핵심 뜻을 떠올리지 못함.
- 어려움: 핵심 뜻을 떠올렸지만 상당히 어려웠음.
- 보통: 핵심 뜻을 떠올렸음.
- 쉬움: 쉽게 떠올렸음.

네 평가 아래에는 다음 예약 간격을 표시하되, 정확한 등급 의미를 접근 가능한 설명에 함께 둔다.
답을 확인한 뒤 알아보았다는 이유만으로 Easy를 누르지 않도록 첫 사용 시 짧게 안내한다.
타이핑/자동 채점은 첫 버전 범위에 넣지 않고 자가 평가를 사용한다.

| 초기 학습 단계 | (1분, 10분) 두 단계 (Gate A 보정 추천, 승인 전) | 첫 Good도 10분 뒤 재확인. Easy는 단계를 건너뛸 수 있음. 라이브러리 기본값과 같음 |
| 재학습 단계 | 10분 한 단계 | 초기 설정 제안, 실패 시 장기 기억을 모두 삭제하지 않음 |

단계 수치가 모든 등급에서 정확히 그 간격이 된다는 뜻은 아니다. Hard/Easy와 단계 진입/종료는 라이브러리 규칙을 따른다.
임의의 간격 재정렬이나 버튼별 고정 배수를 추가하지 않는다. 첫 버전은 단기 단계와 당일 FSRS 업데이트를 조합한 동작을 테스트해야 한다.
시간에 따른 회상 확률 R, 안정도 S, 난이도 D의 갱신은 엔진 결과를 그대로 사용한다.

근거: FSRS 모델은 D/S/R을 구분하며, 공식 Python 구현은 목표 유지율/학습 단계/재학습 단계/최대 간격을 설정할 수 있다.
이 문서의 학습 단계/365일은 외부 연구의 확정 추천으로 인용하지 않는다. (1분, 10분)·재학습 10분은 fsrs 6.3.2 기본값과 같지만, 그것이 최적이라는 근거는 아니다. 단계별 첫 평가 결과는 소스 기반 계산이며 실제 실행 검증 전이다.
[알고리즘 문서](https://github.com/open-spaced-repetition/awesome-fsrs/wiki/The-Algorithm), [공식 구현](https://github.com/open-spaced-repetition/py-fsrs)

## 5. 출제 순서와 동적 세션

오늘 기본 큐는 다음 우선순위로 만든다.

1. 시간이 된 학습/재학습 카드.
2. 시간이 된 장기 복습 카드.
3. 오늘 신규 도입 가능량 안의 미학습 카드.

- 미래 예정 카드는 기본 큐에 미리 넣지 않는다. 장기 복습은 due 시각 우선, 동률은 반복적인 고정 순서 학습을 피하는 순서를 사용한다.
- 범위/권한/참여/미학습 또는 due 필터를 서버에서 적용한 뒤 페이지/세션 크기를 자른다.
- 재학습의 due가 세션 중 도래하면 현재 카드를 마친 다음 우선 출제한다. 진행 중 카드를 타이머가 교체하지 않는다.
- 타이머, 앱 복귀, 세션 다시 열기 때 서버와 큐를 재확인한다. 오래된 탭의 클라이언트 시계만으로 due를 결정하지 않는다.
- 할 카드가 없고 미래 단기 카드만 남았으면 대기 시간을 표시하고 종료할 수 있게 한다. 기다려야만 완료 화면에 갈 수 있는 구조는 피한다.
- 세션은 작은 단위로 끝낼 수 있다. '이번 회차 마침', '오늘 남음', '곧 다시 확인'을 구분하며, 새로 시간이 된 카드가 있어도 예전 세션 완료 문구를 숙련 완료로 바꾸지 않는다.
- 보류/구독 해제/계정 전환 시 이전 카드를 적용하지 않는다. 기존 이어하기/바꾸기/취소 보호를 유지한다.
- 같은 구독 lexeme는 여러 덱에서 중복 출제하지 않는다. 개인+구독 이력은 별도이므로 같은 표제어라는 이유로 합치지 않는다.

정해진 숫자의 큐를 받아 한 번씩 끝내던 기존 구조에서 서버의 카드 상태/시간을 기준으로 갱신하는 구조로 바뀐다.

## 6. 하루량과 학습 계획

기존의 Q는 권장량만이고 큐를 자르지 않는다. 새 설계는 아래 방식으로 실제 신규 도입 목표에 반영할 것을 제안한다.

```text
계획 덱의 오늘 남은 신규 목표
  = max(0, 계획 Q - 오늘 이 덱에서 처음 평가한 서로 다른 카드 수)

실제 신규 도입 수
  = 계획 덱 목표, 계정 전체 하루 신규 목표 잔여량, 미학습 잔량 중 최소
  (목표이지 엄격한 상한이 아님. 여러 기기에서는 넘을 수 있음)
```

- 첫 Again도 신규 도입 1개다. 그 카드의 같은 날 두 번째 평가는 복습 1회이지 신규 1개가 아니다.
- 구독 진도는 계정+lexeme라 다른 구독 덱에서 먼저 평가한 같은 lexeme도 해당 덱의 접함에 반영된다. 신규 실적은 이 기준과 일치하게 중복 제거한다.
- 개인 카드별, 구독 user+lexeme별 식별자를 보존한다. 두 종류를 통합한 '고유 일본어 단어 수'로 잘못 합산하지 않는다.
- Q=0이면 신규 도입만 멈춘다. 이미 학습 중/복습/재학습 카드는 계속 보여 준다.
- 오늘 목표를 달성하면 신규를 기본 큐에서 멈추되, 명시적 '새 단어 더 학습'으로 추가량을 선택할 수 있다.
- 추가량 확인 없이 '한 번 더'로 일일 신규 목표를 우회하지 않는다. 복습 카드에는 신규 목표를 적용하지 않는다.
- 복습이 밀려 있으면 남은 복습과 신규가 추가할 부담을 보여 주고 신규를 줄이거나 오늘 쉬게 할 수 있다. 임의로 due를 뒤로 밀어 목표를 지킨 척하지 않는다.
- 일일 실적의 경계는 Asia/Seoul 00시다. 저장/FSRS 계산 시각은 UTC다.
- 계획 목표일이 지나도 복습 참여를 자동으로 종료하지 않는다. 미래 시작일은 명시적으로 미리 학습할 수 있다.

신규 실적은 서버 트랜잭션에서 정확히 센다(같은 카드 중복 집계 없음). 1단계는 이 집계와 큐 재조회로 신규 출제를 멈추는 **하루 신규 목표**이며, 서버가 실제 화면 표시를 알 수 없으므로 여러 기기의 엄격한 상한은 보장하지 않는다. 엄격한 상한(예약)은 후속 작업으로 분리하고 TTL·자정·평가 중 만료·유예를 별도 승인한다.
서버의 계정 전체 하루 신규 목표 설정은 새 데이터 계약 후보다. 기존 활성 계획은 계정별 이 기기 하나를 그대로 유지하며, 계획 자체의 서버 동기화를 묶어서 구현하지 않는다.
기기별 계획 Q가 달라도 서버의 계정 전체 목표를 몰래 바꾸지 않는다. 기본 계정 목표는 20개 후보이며 아직 승인 전이다.

## 7. 학습 완료 기준 초안

첫 버전의 '학습 완료'는 주요 의미의 학습 목표 달성이다. 모든 뜻을 완벽하게 암기했다는 보장은 아니다.
FSRS에 학습 완료라는 종결 상태가 있는 것이 아니므로 아래는 우리 제품의 **임시 검증 기준**이다. 완료 뒤에도 유지 복습이 이어진다.

다음 조건을 모두 충족한 카드에 학습 완료 표시를 제안한다.

1. 현재 FSRS 상태가 Review다.
2. 모델 안정도 S가 30일 이상이다.
3. 마지막 Again 이후 서로 다른 서울 날짜에서 성공 평가(Hard/Good/Easy)가 2회 이상 있다.
4. 그중 최소 한 번은 직전 유효 평가 이후 실제 7일 이상 지난 뒤의 성공이다.

- 같은 날 반복해서 맞히거나 첫 Easy 한 번으로 학습 완료에 도달하지 못한다.
- 30일/2일/7일은 외부에서 확정된 보편적 기준이 아니다. 시뮬레이션과 실제 지연 회상 결과를 보고 보정할 초안이다.
- R>=0.90을 완료의 단독 조건으로 쓰지 않는다. 오늘 새로 본 카드도 일시적으로 R이 높을 수 있다.
- 다음날 R이 내려갔다는 이유만으로 완료 진도를 매일 줄이지 않는다. 현재 확인 필요 여부는 due/R로 따로 알린다.
- 실패하거나 현재 상태/안정도가 기준 아래로 내려가면 현재 완료 수는 감소할 수 있다. 이때 '재학습 필요'로 표시하고, 과거 완료 달성 이력은 별도로 보존한다.
- 보류 카드도 완료 이력은 보존하지만 현재 덱의 완료 분자에는 포함하지 않는다. 보류 수를 별도 표시한다.

덱 진도는 현재 카드 집합에서 계산한다.

```text
첫 학습 진도 = 실제 첫 평가가 있는 카드 / 전체 카드
학습 완료 진도 = 위 완료 기준을 충족한 참여 카드 / 전체 카드
보류 = 학습에서 보류한 카드 수 (완료 수와 별개)
```

빈 덱이 아닌 덱 전체가 완료 기준에 도달하면 '학습 완료'로 표현한다. 계속 유지 복습이 필요하며, '복습 종료'로 표현하지 않는다.

## 8. 예상 기간

두 예측을 구분한다.

- 첫 학습 예상일: 미학습 잔량과 오늘 남은 도입량/이후 Q로 계산한다. 오늘 이미 도입한 양을 빼지 않고 Q 전체를 또 부여하면 안 된다.
- 학습 완료 예상: 평가 성공/실패, 간격, 일일 가능량, 향후 출석 가정으로 시뮬레이션한 범위다. 특정 날짜를 확정 보장하지 않는다.

이력이 부족하면 완료 예상은 '학습 이력 필요'로 둔다. 샘플의 5~7주 같은 값은 실제 계산 없이 제품 화면에 넣지 않는다.
시뮬레이터가 아직 없으면 첫 학습 예상일과 현재 완료 진도까지만 출시하고, 완료 예상일을 대신 첫 학습 날짜로 채우지 않는다.
계획에 사용자가 정한 목표일은 목표이며, 시스템의 예상 범위와 분리해서 표시한다. 기간이 짧으면 신규량 증가만으로 학습 완료가 보장되지 않음을 알려 준다.

## 9. 화면 구성 방향

읽기: 기존 종이 장면/분류 4종 유지. 기본 원문에 기억 확률 수치를 늘어놓지 않는다.
단어 상세: 필요한 경우 '복습 중/보류', 다음 복습 시각을 작게 확인할 수 있다.
복습: 덱/미학습·복습·재학습 수, 단어 질문, 정답, 네 평가+다음 간격. 뜻 수정/신고는 기존 구석 도구 위치를 유지한다.
계획: 덱 → 기간 → 하루 신규량 → 첫 학습/학습 완료 진도 두 줄 → 시작. 오늘 복습 수는 신규량과 별도 줄이다.
통계: 신규 도입 개수, 평가 횟수, 시간 간격을 둔 성공률을 구분한다. 자기분류 known 수를 학습 완료 수로 바꾸지 않는다.

표시 예시(합성값, 실제 모델 계산 아님):

```text
오늘   새 단어 7 / 10개    복습 18개 남음
진도   첫 학습 120 / 200   학습 완료 45 / 200
일정   첫 학습 예상 10월 16일   완료 예상: 학습 이력 필요
```

이 단계에서 새 디자인 목업/에셋을 만들지 않는다. FSRS 지표를 이유로 기존 지면에 통계 카드/설명 문단을 계속 추가하지 않는다.

## 10. 평가 저장과 안전성

평가 요청은 서버가 인정한 현재 계정/카드 버전/세션 문맥으로 처리한다.

1. 같은 요청 식별자의 재전송은 같은 결과를 돌려주고 이력/신규 실적을 또 증가시키지 않는다.
2. 카드 상태 변경, 로그, 오늘 실적은 한 트랜잭션이다. 서로 다른 창에서 같은 이전 카드 버전을 평가하면 한 요청은 충돌 처리한다.
3. 응답 실패만으로 카드를 넘기지 않는다. 응답 유실은 같은 요청 ID로 결과를 확인한다.
4. 계정/세션이 바뀌면 이전 응답은 새 화면에 적용하지 않는다. 이미 서버가 승인한 이전 계정의 평가를 새 계정으로 옮기지 않는다.
5. 당장 이전 평가 되돌리기는 해당 카드 이후 평가가 없고 버전이 맞을 때만 허용하는 후속 계약 후보다. 이벤트를 조용히 삭제하지 않고 취소 흔적과 상태 복원을 남긴다.
6. 되돌리기를 제공한다면 seen/오늘 신규/통계/완료 지표도 같은 기준으로 다시 계산한다. 화면 숫자만 줄이는 구현은 금지한다.
7. 기본 엔진은 자가 평가와 경과 시간을 사용한다. 현재 response_time_ms를 기억 속도로 해석하지 않는다. 오프라인 평가 동기화는 첫 버전 범위에 넣지 않는다.

## 11. 기존 자료 이전

- 개인/구독의 카드 정체성과 권한을 유지한다. 원문 전체를 서버에 새로 올리지 않는다.
- 기존 로그가 충분하고 일관되면 시각 순서로 재생해 FSRS 상태를 계산한다. review_level을 안정도 일수로 임의 변환하지 않는다.
- 불완전 이력은 사용자 이력/예약을 보존하며 보수적 초기화 정책을 따로 승인받는다. 불완전 이력으로 학습 완료를 자동 인증하지 않는다.
- 기존 known은 예전에는 복습 제외 의미도 있었으므로, 새 버전에서 한 번에 몰래 재참여시키지 않는다. 기존 제외를 보존하고 '기존 아는 단어도 복습에 포함' 선택으로 재참여하는 이전안을 권한다.
- 기존 known의 자기분류와 이력은 그대로 둔다. 신규 엔진을 켠 뒤의 Easy는 참여를 종료하지 않는다.
- 기존 due는 일괄로 전부 앞당기지 않는 전환을 우선 검토한다. 백업/되돌리기/엔진 버전과 파라미터 버전을 남긴다.
- 이력을 외부 서비스에 전송하는 최적화는 포함하지 않는다. 운영 DB의 직접 로컬 접근도 금지한다.

## 12. 구현 전 승인 항목과 단계

기본 원리와 별도로 다음 수치/계약은 사용자 승인이 필요하다.

- 의미 인출 우선, 자기분류와 참여 분리, 기존 known의 동의 기반 재참여.
- 유지율 90%, 초기 학습 (1분, 10분)·재학습 10분 한 단계, 최대 간격 365일, fuzz 끔.
- 하루량의 권장량 → 실제 신규 도입 목표 전환, 계정 하루 신규 목표(20개 후보)/추가량 방식. 엄격한 다중 기기 상한은 후속 별도 승인.
- 임시 학습 완료 기준 S>=30일 + 실패 이후 서로 다른 날 성공 2회 + 7일 이상 간격 성공 1회.
- 계정 전체 SRS 설정의 서버 저장과 신규 API/스키마 범위. 계획 저장 자체는 기존 로컬 계약 유지.

권장 구현 순서:

1. 계약/학습 완료 기준 확정, 평가 응답 경합을 실제 앱에서 재현.
2. 버전 고정 엔진 어댑터, 이력/스키마/이전/되돌리기와 비활성 비교 모드 설계.
3. 동일한 합성 시각/등급에서 엔진·단기 전이·신규 목표 집계·권한·중복 평가 테스트. 세션 SQLite와 보호된 빈 로컬 PostgreSQL로 비교.
4. 동적 큐와 기존 복습 UI 연결. 계정/세션/두 창/응답 유실 보호 확인.
5. 계획/통계 지표를 분리해 연결. 데이터가 없으면 완료 예상일은 미제공.
6. 시간 분리 예측 검증과 실제 지연 회상/학습 부담 관찰 후 기준 보정. 타입/회귀/최종 빌드와 시각 검증 후 출시 승인.

이 문서 작성은 설계 작업이다. 제품 코드 수정, 의존성 설치, 실제 사용자 이력 이전, 브랜치/커밋/푸시는 하지 않았다.
