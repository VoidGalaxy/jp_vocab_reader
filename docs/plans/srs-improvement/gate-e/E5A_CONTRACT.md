# E-5a 계정 쓰기 경계

2026-10-19 · 보완안 승인 후, 구현 전 기록.

## 계약

- 기존 계정의 쓰기는 저장 연결의 같은 transaction 안에서 계정 행을 먼저 확인한다.
  SQLite는 BEGIN IMMEDIATE 뒤 SELECT, PG는 users 행 SELECT FOR UPDATE다.
  잠금은 실제 커밋/롤백까지 유지한다. 인증 연결의 확인으로 대신하지 않는다.
- 없는 계정은 기존 의미의 404 account_not_found이며 내용·쓰기 없이 끝난다.
  기존 SRS 경로의 오류 타입·코드, 없는 카드의 404, 정상 요청 응답은 유지한다.
- 기존 SRS begin_card_write 호출은 유지하되 공용 계정 경계를 사용한다.
  새 경계는 SRS 엔진/모드/열 유무와 무관하다. 구 스키마에도 users는 필요하다.
- 단어·덱·용어 생성/수정/삭제, 예문/설명 갱신, 패키지 가져오기, 공유 발행/
  취소/재공개/가져오기, 구독·진도·평가, 피드백 쓰기를 포함한다.
- 공유 발행의 lexeme/공유 단어 쓰기와 구독의 카운터 갱신은 상위 계정 잠금과
  같은 연결로 묶는다. 하위 helper는 외부 호출 호환을 유지하고 선택 연결을 받는다.
  내부 helper에 전달하는 연결의 transaction과 잠금은 상위 호출자가 소유한다.
- 공유 발행은 정규화된 공용 단어 키 순서로 쓰고, 원래 덱 내 순서는 sort_order로
  보존한다. 서로 다른 계정의 반대 순서 발행이 lexeme 잠금을 뒤집지 않도록 한다.
- 계정 생성과 dev 계정 provisioning, 전역 사전/패키지 seed, 초기화는 기존 계정
  쓰기와 구분한다. 서비스 쓰기 경로 목록을 검사해 새 경로가 조용히 빠지지 않게 한다.
- 익명 app_feedback(user_id NULL)은 기존 내부 계약대로 허용한다. HTTP의 기존
  방문자는 dev 계정에 속하므로 그 id의 존재 확인을 건너뛰지 않는다.
- 삭제 기능은 아직 없다. 테스트는 합성 계정을 최소 절차로 지워 지연 요청과
  경합을 재현한다. 이 절차를 제품 계정 삭제 도구로 노출하지 않는다.

## 검증

1. 수정 전 삭제된 계정의 단어/덱/용어/구독/진도/평가/피드백 재생성을 고정한다.
2. 모든 대상 저장소 쓰기에서 삭제 후 404, 행/내용/로그/영수증 변화 0을 확인한다.
3. 실제 겹친 실행 두 순서: 쓰기 먼저면 삭제가 기다린 뒤 자료 제거, 삭제 먼저면
   쓰기가 기다린 뒤 404. 예상 밖 예외·교착·대기 초과는 성공으로 인정하지 않는다.
4. 공유 발행·구독 중 실패는 전체 롤백, 하위 쓰기 중간에 계정 삭제가 끼지 못한다.
5. HTTP는 인증 통과 후 삭제를 주입해 같은 거부 코드와 내용 비노출을 확인한다.
6. 보호된 로컬 PG에서 실제 대기 상대를 확인한다. SQLite·PG 결과는 구분한다.
7. 기존 legacy/FSRS/이전/학습계획/공유 회귀를 유지한다. 운영 DB는 열지 않는다.

## 제한

계정 삭제 전체(P-ACC), 법정 보존 판단, 공유 덱의 최종 수동 처리, 요청/통지 UI,
백업 파기, 운영 복구(P-RB)는 이 단위의 완료로 간주하지 않는다.
