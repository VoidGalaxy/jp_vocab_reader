# E-5 삭제 정책의 한국 법률 사전 검토

확인일: 2026-10-19. 범위: 한국 개인정보 보호 법령과 현재 저장소의 삭제 설계.
제품 코드·스키마·운영 자료 변경 없음. 법률 전문가의 개별 자문이나 적법성 인증이 아니다.

후속 진행: 이 검토 뒤 사용자가 보완안을 승인했다. 승인 기록은 APPROVAL_REQUEST.md,
선행 쓰기 경계의 구현·합성 검증은 E5A_CONTRACT.md와 E5A_REPORT.md에 있다.
아래 결론은 조건부 지시를 검토하던 당시 기록이며 운영 적법성 인증으로 바뀐 것이 아니다.

## 1. 결론과 사용자 지시 해석

사용자는 법적인 사항을 확인하고 **이상이 없으면** 기존 권장안으로 진행하라고 했다.
아래 보완 사항이 있어 조건 충족으로 판단하지 않았다. 기존 권장안을 그대로
승인 처리하거나 계정 삭제 기능을 구현하지 않았다. 보완안으로 구현할지 별도 질문을 했다.

특히 E-D3의 공유 덱 소유자 차단은 자동화 안전장치로는 이해할 수 있으나,
삭제·동의 철회 요구에 대한 무기한 거부 사유로 사용할 수 있다는 결론은 내릴 수 없다.
E-D6의 운영자 스크립트는 내부 실행 방식일 뿐, 이용자 권리행사 창구를 대체하지 않는다.
E-D2·E-D5의 전부 삭제는 적용되는 법정 보존 자료가 없는지 확인해야 한다.

한국 운영·한국 이용자 관계를 우선 검토했다. 운영 주체, 유료 거래 유무,
이용자 국가·연령, 실제 개인정보 처리방침·약관, 위탁·국외 이전 현황은 확인되지 않았다.
운영 계정·Neon·기존 vocab.db에는 접속하지 않았다.

## 2. 법령과 설계 대조

### 불필요한 자료의 파기와 예외

개인정보가 불필요해지면 지체 없이 파기하고, 다른 법령에 따른 보존은 별도 관리해야 한다.
학습 로그·영수증·snapshot·원장은 계정과 연결되면 개인정보가 될 수 있다.
단어 삭제와 탈퇴 삭제를 구분하되, 단어 삭제 후 보존의 목적·기간도 따로 정해야 한다.
이번 검토는 카드 삭제 뒤 로그를 영구 보존해도 된다는 승인이 아니다.
[개인정보 보호법 제21조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900078981)

### 공유 덱 때문에 탈퇴를 거절하는 정책

처리정지·동의 철회에는 법정 예외가 있고 다른 사람의 이익도 사안별로 고려될 수 있다.
하지만 공유 덱 소유 사실만으로 계정의 모든 개인정보를 계속 보유해도 된다는 일반
예외는 확인하지 못했다. 이는 원래 안의 권리 제한 위험이라는 **설계상 판단**이며,
모든 차단이 곧 위법이라는 단정은 아니다.
[개인정보 보호법 제37조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0037&lsiSeq=283839&urlMode=lsScJoRltInfoR)

보완 제안: 공유 덱 소유자는 자동 파괴만 중단하고 수동 검토 대상으로 돌린다.
접수 사실·처리 사유·이의 제기 방법을 안내하며 무기한 대기시키지 않는다.
공유 덱 이전·개인 식별정보 분리·내용 삭제 중 어느 방법을 쓸지는 다른 이용자 기록과
내용 사용 권한까지 확인해 별도 설계한다. 임의 소유권 이전이나 삭제는 하지 않는다.

### 요청 창구와 결과 통지

권리행사 방법을 공개하고 수집보다 어렵지 않게 해야 한다. 운영자 CLI 자체가
금지되는 것은 아니나, 공개된 쉬운 요청 방법 없이 내부 도구만 있는 상태는 불충분하다.
담당 연락처·접수·본인/대리인 확인·처리 결과·이의 절차를 갖춰야 한다.
[개인정보 보호법 제38조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0038&lsiSeq=283839&urlMode=lsScJoRltInfoR)

정정·삭제 요구의 처리 결과 통지는 시행령 제43조의 10일 기준을 검토해야 한다.
이를 모든 탈퇴 자료를 10일간 더 보유해도 된다는 유예로 해석하지 않는다.
본인 확인은 시행령 제46조에 따라 처리하며, 운영자가 계정 번호를 재입력하는 것만으로
이용자 본인 확인을 끝냈다고 보지 않는다. 주민등록증 수집을 기본값으로 삼지 않는다.
[시행령 제43조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0043&lsiSeq=289537&urlMode=lsScJoRltInfoR),
[법령·시행령 대조(제46조 포함)](https://law.go.kr/lsInfoP.do?chrClsCd=010202&https%3A%2F%2Flaw.go.kr%2FlsInfoP.do%3FlsiSeq=142563&lsId=011357&urlMode=lsEfInfoR&viewCls=thdCmpNewScP)

### 백업·복제·물리 매체

파기는 복구·재생 방지까지 고려해야 한다. SQL DELETE 후 조회 0행은 서비스 DB의
논리 삭제 근거이지 WAL·복제본·분기·백업·다운로드 사본의 파기 증명은 아니다.
브라우저 자료와 외부 백업을 서버 도구가 지우지 못한다는 사실만으로 책임이 끝나지 않는다.
[개인정보 보호법 시행령 제16조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0016&lsiSeq=289537&urlMode=lsScJoRltInfoR)

보완 제안: 실제 공급자 보존 설정, 삭제 가능 범위, 접근 제한, 만료·파기 확인과
복원 시 삭제 이력 재적용 절차를 확인한다. 일괄 삭제가 어렵다는 이유만으로 보유를
무기한 정당화하지 않는다. 정해진 기간이나 기술적 조치가 적법하다고 이번에 인증하지 않는다.
서버 삭제 결과와 전체 개인정보 파기 완료를 보고에서 구분한다.

### 법정 보존 자료와 피드백

전자상거래법 적용 거래가 있으면 계약·청약철회 및 결제·공급 기록 5년,
소비자 불만·분쟁 처리 기록 3년 등의 별도 의무를 검토해야 한다.
모든 앱 피드백이 해당 거래 기록인 것도, 무료 학습 자료 전부에 이 기간이 적용되는 것도 아니다.
적용 사실과 기록 유형을 확인하고 필요한 항목만 분리 보존해야 한다.
[전자상거래법 시행령 제6조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1018638379)

개인정보취급자 접속기록은 안전성 확보조치 기준 제8조의 보존·보호 대상이 될 수 있다.
일반 학습 평가 로그는 해당 보안 접속기록과 구분한다. 탈퇴 도구가 감사·접속기록을
통째로 삭제하도록 확장하지 않는다. 원문·뜻·이메일을 파기 증적에 불필요하게 복사하지 않는다.
[안전성 확보조치 기준, 2025-9호 본문](https://www.law.go.kr/LSW/lawBodyComparePrint.do?leftGubun=AdmRul&leftSeq=2100000265956&rightGubun=AdmRul&rightSeq=2100000229672)

### 처리방침

목적·보유 기간·파기·권리행사·담당 연락처 등을 처리방침에 공개해야 한다.
현재 `InfoSection.tsx`의 짧은 개인정보·출처 안내와 베타 피드백 문서는 확인했으나,
그것만으로 서비스 전체 처리방침이 충족됐다고 볼 수 없다. 외부 공개 정책 유무는 미확인이다.
[개인정보 보호법 제30조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0030&lsiSeq=283839&urlMode=lsScJoRltInfoR)

## 3. 기존 권장안별 조치

| 항목 | 검토 결론과 보완안 |
| --- | --- |
| E-D2 자료 전부 삭제 | 일반 계정 학습 자료 삭제 방향 유지. 법정 보존 적용 여부와 외부 사본을 먼저 확인 |
| E-D3 공유 덱 소유자 | 영구 거절로 확정하지 않음. 자동 삭제 중단 + 별도 검토 제안, 후속 해결 경로 필수 |
| E-D4 카드 삭제와 구분 | 구분 유지. 계정 내부 학습 로그도 목적·기간 없이 무기한 보유하지 않음 |
| E-D5 피드백 삭제 | 일반 피드백 삭제 방향. 법정 거래 불만·분쟁 자료라면 필요한 부분 분리 보존 검토 |
| E-D6 운영자 도구 | 내부 실행 방식 유지 가능. 쉬운 외부 요청 창구·본인 확인·결과 통지 별도 필요 |
| E-D11 B 쓰기 경계 | 삭제 후 부활 방지에 필요한 안전 방향. 다만 이번 조건부 지시만으로 별도 선행 구현하지 않음 |
| E-D7 공유 원본 보호 | 서비스 무결성 보호일 뿐 개인정보 삭제 요구의 거절 근거로 일반화하지 않음 |

7일 영수증·30일 롤백 기간은 제품 계약값이다. 법정 보존기간이 아니며, 탈퇴 자료를
그 기간까지 무조건 남기거나 모든 법정 보존 의무를 그 기간으로 대신하지 않는다.

## 4. 구현·운영 전 확인할 사실

- 운영 주체와 서비스 국가, 유료 기능·거래·분쟁 기록 유무.
- 개인정보 처리방침·약관·공유 콘텐츠 사용 조건과 공개된 요청 담당 창구.
- 미성년자 이용 범위와 법정대리인 절차가 필요한지.
- Neon·호스팅·분석·메일·AI 처리 등의 실제 위탁/국외 이전·로그·백업 보존 현황.
  이번에 외부 서비스에 접속해 확인하거나 해당 정책 전체를 감사하지 않았다.
- 이용자가 업로드한 공유 자료나 다른 사람의 사본에 개인정보가 포함된 경우의 처리.
  숫자 계정 id를 떼는 것만으로 익명 정보라고 단정하지 않는다.
- 파기 실행자·승인·시각·처리 결과의 최소 증적과 접근 통제, 증적 자체의 보유 기준.

위 사실을 모르는 상태에서 유료 거래가 없다거나 법정 보존 자료가 없다고 자동 가정하지 않는다.
실제 탈퇴 도구의 운영 활성화와 실행은 이 확인과 별도 대상 승인이 끝난 뒤에 한다.

## 5. 이번 결과

법적 보완 필요 사항을 발견했으므로 조건부 구현 지시는 아직 실행하지 않았다.
법률 검토와 문서 대조만 수행했으며 제품·테스트 코드, 스키마, DB를 바꾸지 않았다.
보완안 승인 후 합성 자료로 E-5a 쓰기 경계부터 구현하고, E-5b 삭제와
E-5c 경합 검증을 진행한다. 운영·실제 사용자 자료·커밋·푸시·병합은 포함하지 않는다.
