# E-D13 Codex 검토 (2026-10-19)

대상: REPORT 13절, PG 초기화의 무변경 DDL 생략 구현.
제품 파일·스키마 정책 변경 없이 코드 검토와 합성 재현을 수행했다.

## P2-1. 다른 인덱스 정의를 정상으로 오판

위치: backend/app/srs/schema.py:325, 334~350.

현재 판정은 indkey 전체의 열 이름을 비교하지만, 검색 키와 INCLUDE 열을 구분하지 않는다. 정렬 옵션·연산자 클래스도 비교하지 않는다.

실제 로컬 PG 18.6에서 기대 인덱스 `idx_vocab_items_srs_queue`를 다음 세 형태로 각각 바꿨다.
- 기대: `(user_id, srs_engine, srs_participation, srs_effective_due_at)` 네 검색 키.
- 사례 A: `(user_id, srs_engine) INCLUDE (srs_participation, srs_effective_due_at)` — 검색 키 2, 전체 속성 4.
- 사례 B: 마지막 검색 키에 DESC NULLS FIRST.
- 사례 C: srs_engine에 text_pattern_ops.

세 사례 모두 ensure_pg_index가 False(생성 불필요)를 반환했고, 전체 init_db도 성공했다. 원래 oid·다른 정의는 그대로였다. 이는 “정의가 다르면 중단” 계약과 맞지 않으며, 특히 INCLUDE 열은 큐 정렬용 검색 키를 대신하지 않는다. 데이터 손실을 재현한 결과는 아니다.

보정 방향:
- 검색 키 수와 INCLUDE 구성, 키별 정렬 옵션·연산자 클래스 등 승인된 기본 인덱스 정의를 구조화된 카탈로그 정보로 대조한다.
- 다른 정의는 자동 복구 없이 SchemaUpgradeError로 중단하고 트랜잭션을 롤백한다.
- 위 세 사례를 실제 PG 회귀로 추가하고 정상 기본 정의도 함께 확인한다.

## P2-2. 동시 DDL 기록기의 전역 패치가 충돌

위치: backend/tests/test_srs_e13_init_ddl_real.py:41~58, 153.

각 작업자가 같은 AppPostgresConnection.execute를 별도로 patch한다. 중첩 진입 뒤 먼저 진입한 작업자가 먼저 끝나면, 아직 실행 중인 다른 기록기의 패치까지 해제된다. 마지막 종료는 앞선 래퍼를 되살릴 수 있다.

DB 없는 실제 두 스레드·Event 제어 재현:
1. A 기록기 진입 → B 기록기 진입 → A 기록기 종료.
2. B가 합성 드라이버를 통해 ALTER TABLE 1건 실행.
3. 드라이버 실행 수는 1이지만 B의 DDL 기록은 빈 목록이었다.
4. B 종료 뒤 클래스 메서드는 원래 함수가 아니었다. 검토 스크립트의 finally에서 직접 원복했다.

따라서 현재 “4개 작업자 모두 DDL 0” 측정은 이 계측만으로 확정할 수 없다. 제품 자체가 DDL을 실행했다고 단정하는 지적은 아니다.

보정 방향:
- 작업자 시작 전 패치를 한 번만 설치하고 모든 작업자가 종료된 뒤 한 번만 복원한다.
- 스레드/연결별로 기록을 분리하고, 기록 수집을 동기화한다.
- 실행 DDL 누락 0, 다른 작업자 기록 혼입 0, 정상·예외 종료 뒤 메서드 복원을 부정 대조로 검증한다.

## 범위와 정리

- 실제 PG 검토는 보호된 빈 로컬 DB·제한 역할·기존 E-1/2 장치로 수행했다. 제품 파일은 수정하지 않았다.
- 인덱스 진단 후 소유 객체 정리, public 관계 0 확인. 이번에 시작한 소유 PID·실행 파일·자료 경로를 확인해 PG를 종료했고 55432 리스너가 없었다.
- 운영·Neon·기존 vocab.db 접근, 스테이징·커밋·푸시·병합 없음. 설치·자료 폴더 보존.
- 기존 33개 PG 묶음·SQLite 전체·회귀 스크립트를 이번 검토에서 재실행한 결과는 아니다.
- 판단: 위 두 보정 후 E-D13 재검토. 실제 변경이 필요한 업그레이드의 기존 교착 위험은 별도 운영 절차가 필요한 상태로 유지한다.

## 후속 보정 (2026-10-19)

사용자 요청으로 Codex가 두 건을 직접 보정했다. 검색 키·INCLUDE·기본 정렬·opclass·collation을 검증하고, 기록기를 작업자 밖에서 한 번만 설치해 스레드·연결별로 수집한다. 정상·예외 종료 뒤 복원도 확인했다.

실제 PG 인덱스 정의 5종 × 두 경로 거부·무변경 보존, PG 포함 회귀 묶음 34개(33 통과·기존 위험 1 예상된 실패), SQLite 전체 779개(748 통과·PG 31 건너뜀), 기록기 반복 80/80과 회귀 스크립트 9종을 확인했다. 상세는 REPORT 14절이다. 위 지적은 수정 전 검토 기록으로 보존한다.
