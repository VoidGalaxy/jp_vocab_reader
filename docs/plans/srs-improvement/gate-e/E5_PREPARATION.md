# E-5 준비: 읽기 전용 계정 자료 조사

2026-10-19 · `codex/fsrs-srs-replacement` · HEAD `e2c07f8`

진행 갱신: 법률 사전 검토 후 사용자가 보완안을 승인했다. E-5a 쓰기 경계 구현과
검증 결과는 `E5A_REPORT.md`에 있다. 아래는 그 이전의 준비 기록이며,
실제 삭제 도구와 운영 처리까지 완료된 것은 아니다.

## 범위와 승인

사용자가 다음 작업 진행을 요청했다. 기존 승인 기록에서 E-D2~E-D6과 E-D11은
여전히 미승인이므로 이번 요청을 해당 정책 전부의 승인으로 해석하지 않았다.
권장 정책 묶음에 대한 질문을 별도로 제시했다. 이 문서는 승인 기록이 아니다.

이번 단위는 **테스트 장치와 합성 SQLite 검증만**이다. 제품 코드·스키마·API·
화면·삭제 절차·운영 도구는 변경하지 않았다. 실제 삭제나 운영 복구를 하지 않는다.

## 만든 것

- `backend/tests/_srs_e5_preflight.py`: 이미 보호된 연결을 받아 하나의 읽기 전용
  snapshot 안에서 계정 자료 건수와 소유 관계를 조사한다. 자체 연결·초기화·쓰기 없음.
- `backend/tests/test_srs_e5_preflight.py`: 제품 스키마로 생성한 합성 SQLite만 사용.

현재 앱 표 24개를 명시적으로 분류한다. 계정 열이 있는 16개 표, users,
shared_decks, srs_migration_runs, 전역·공유 하위 자료 5개다. 새 표·누락 표가
있으면 건수를 0으로 가정하지 않고 `incomplete`로 멈춘다. 열·FK·트리거 정의
전체를 검증하는 장치는 아니며, 실제 삭제 전에는 별도 의존 관계 검사가 필요하다.

실행의 소유 계정은 scope 최상위의 정수 user_id만 읽는다. 파싱 불가·중복 키·
잘못된 타입·과대 id는 추정하지 않는다. 어느 계정의 실행인지 모르면 전체 조사
결과를 불완전으로 둔다. snapshot과 부모 실행의 소유자가 양방향으로 어긋나는
경우도 센다. 다른 계정 자료를 대상 계정 것으로 자동 편입하지 않는다.

공유 덱 소유 수와 진행 중 실행 수는 관찰값만 반환한다. 정상 조사의 상태도
`inventory_complete`일 뿐, 삭제 가능/승인/적용 계획이 아니다.
`deletion_enabled`는 항상 false다. 이메일·원문·표제어·뜻·scope 내용·실행 id는
반환하지 않고 건수와 고정 사유만 반환한다.

## 검증

- 새 검사 13개: 계정 분리, 내용 비노출, 표 목록 누락/추가, 손상 scope,
  중복 키, 계정 id 타입/범위, 계정 없음, 교차 소유 snapshot, 부모 확인 불가,
  진행 중 실행, 공개/비공개 공유 덱 소유, 예외 시 snapshot 종료.
- SQLite 조회 전후 파일 바이트 동일, 연결의 total_changes 동일,
  읽기 전용 transaction 종료와 설정 복원 확인. 쓰기 SQL 없음.
- 기존 로컬 PG 보호 검사 12개, 엔진 28개, 완료 21개 통과.
- 합계 74개 통과. 전체 백엔드·실제 PG·브라우저·프론트·빌드 재실행은 하지 않았다.
  이 결과로 P-ACC 또는 P-RB를 완료 처리하지 않는다.

초기 시험은 기존 HTTP Scenario fixture를 재사용하다 첫 테스트가 끝나지 않아
직접 중단했다. 그 실행은 통과로 세지 않았다. HTTP가 필요 없는 검사이므로
fixture를 실제 스키마 + 저장소 계정 생성 + 합성 SQL로 분리해 다시 실행했다.
최초 fixture의 합성 DB 폴더만 확인 후 정리했다. TestClient 중단 원인을 제품
결함으로 판정하거나 기존 테스트의 기대값을 바꾸지는 않았다.

## 승인 후 구현 순서

1. **E-5a 쓰기 경계**: E-D11 B 승인 시, 계정 존재를 계정 잠금과 같은
   transaction에서 확인한다. SQLite BEGIN IMMEDIATE 뒤 SELECT와 PG 사용자
   행 잠금을 맞춘다. 쓰기 라우트와 운영 쓰기 목록을 대조하고 누락을 검사한다.
   중첩 연결을 여는 공유 덱·lexeme 경로도 포함한다. 기존 계정 생성은 구분한다.
2. **E-5b 삭제 도구**: 범위·공유 덱·피드백·운영자 도구 정책 승인 후 기본 dry-run,
   계정 확인, snapshot/실행부터의 명시 순서, 한 transaction, 잔존 검사,
   다른 계정 보존을 구현한다. 실제 사용자 실행은 별도 승인이다.
3. **E-5c 경합**: 인증 직후 삭제와 반대 순서, 평가·이전·카드 생성·구독·피드백
   등 전체 경로를 실제 겹친 실행으로 검증한다. PG는 기존 보호 장치를 사용한다.
4. **복구는 별도**: E-D12 승인 전 모드 변경 도구를 만들지 않는다.
   쓰기 차단 → dry-run → 롤백 → 잔존 FSRS 확인 → 모드 변경 원칙을 검토한다.
   만료·차단 카드가 남으면 자동 강제 복구하지 않는다.

미승인 E-D7·E-D9·E-D10·E-D12를 이 작업으로 승인 처리하지 않는다.
계정 삭제는 브라우저 저장소와 외부 백업까지 지우지 못한다는 한계도 유지한다.

## 종료

운영·Neon·기존 vocab.db·로컬 PG에 접속하지 않았다. 서버를 켜지 않았다.
기존 변경·기존 임시 폴더는 보존했다. 스테이징·커밋·푸시·병합 없음.
E-5 준비 완료, 정책 승인 대기. Gate E 전체 완료나 운영 전환 준비 완료가 아니다.
