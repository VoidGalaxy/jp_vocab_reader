### 2-1. 권한 (계약 표 4-4-4 = `srs_migrate.READ_PRIVILEGES`·`WRITE_PRIVILEGES` 그대로)
- `jpvm_read`: 두 스키마 USAGE, 식별 표 SELECT, `READ_TABLES` 10개 SELECT, 검사 DB `CONNECT`.
- `jpvm_write`: 읽기 권한 + `users` `SELECT(id)`·`UPDATE(updated_at)`, `account_write_blocks` SELECT, `srs_migration_runs` INSERT·`UPDATE(finished_at, status, summary_json)`, `srs_migration_snapshots` INSERT, `srs_config_versions` SELECT·INSERT, 두 시퀀스 USAGE, `vocab_items`·`user_word_progress`의 `CARD_UPDATE_COLUMNS` 18열 UPDATE.
- 그 밖 표·열·시퀀스 권한 없음. 관측된 권한으로 이 목록을 고치지 않는다. 다르면 `observed_privileges_*` 거부이고 결함 후보로 보고한다.
- 관측 대상 목록(`ProfileScope.objects`)은 C12-1에서 `ensure_schema` 정적 목록 + 식별 스키마·표로 코드에 고정하고 실행 전에 검토받는다.

### 2-2. 스키마·합성 자료 준비 (C12-2)
1. 앱 import 전 `APP_ENV=test`, `DATABASE_URL=sqlite:///:memory:`, `PYTHON_DOTENV_DISABLED=1`을 고정한다. `init_db`·`initialize_database`·`get_connection`은 호출되면 실패하도록 막는다.
2. 원본 DB에 관리 연결(SSPI) → `SET ROLE jpvm_owner` → `AppPostgresConnection`으로 감싸 `app.database.ensure_schema(conn)` → 커밋.
3. 같은 소유 역할로 고정 SQL 합성 자료: 계정 A(개인 카드 3, 활성 구독 덱의 어휘 카드 2, `blocked` 후보 1), 계정 B(같은 형태의 대조 카드), 계정 C(다른 계정 같은 키 경합 전용), 범위 밖 카드(계정 A의 다른 카드). 각 카드의 `review_logs`·`lexeme_review_logs`는 전환 후보·`blocked` 품질이 코드상 나오도록 C12-1에서 기존 제품 시험 자료와 대조해 정한다. 의도한 품질이 자료로 나오지 않으면 자료나 기대를 바꾸지 않고 준비 실패로 멈춘다.
4. 넣은 행 수·카드 ID·계정 ID(합성값)만 생성 기록에 남긴다.
5. 계획 파일·승인·백업 근거는 검사 DB 생성 뒤 실행기가 시험 서명 키로 만든다(계획 파일의 `db_identity`는 그 DB의 관측 식별값).

## 3. 실제 드라이버 위치와 보호 조건

- 실제 드라이버(`psycopg.connect`)는 새 시험 전용 실행기 `backend/tests/_ops_apply_real.py`(명시 실행 `prepare`·`check`·`cleanup`, import만으로 외부 작업 없음)에만 둔다. 실행기는 자신이 감싼 드라이버를 `srs_migrate.run_apply(..., driver=...)`에 넘긴다. `scripts/`의 공급자·어댑터·CLI `main`·운영 모드·기본 진입점은 바꾸지 않으며 계속 거부한다.
- 연결 전(연결마다): 호스트 `localhost`, 포트 55492, DB는 4절 목록, 역할은 `jpvm_read`·`jpvm_write`만, `sslmode=verify-full`, PG 환경 변수·`PGSERVICE` 등 있으면 거부. `data/postmaster.pid`의 PID = 생성 기록, 그 PID의 실행 파일 = 기록된 `postgres.exe`, 55492 리스너 소유 PID = 그 PID.
- 연결 후(관측 트랜잭션 안): 루프백 주소, `inet_server_port()` = 55492, `server_version_num` = 기록, DB OID = 기록, 식별 행 = 그 DB의 기록 nonce, 역할 OID = 기록.
- 생성 기록(`record.json`, 비밀 없음): 데이터·실행 파일 경로, 포트, postmaster PID, `system_identifier`, 역할·DB 이름과 OID, 객체 OID(검사 DB의 표·시퀀스), 인증서 SHA-256, nonce. 기록 SHA-256은 각 검사의 시험 승인 문서에 결속한다.
- 관리 연결은 별도 함수에서 SSPI로만 열고, 공급자를 거치지 않으며, 허용 문장은 이 문서의 준비·권한 변형·원복·관측 탐침·정리 목록뿐이다.
- **잔존물 중단**: 시작 전 경로·포트·역할·DB가 이미 있거나, 실행 중·정리 전 관측(PID·실행 파일·리스너·OID·nonce)이 기록과 다르면 자동 정리하지 않고 중단한다. 상태만 기록하고 사용자 판단을 기다린다.

## 4. 실제 PG 검사표

### 4-0. 판정 용어 (2026-10-27 검토 보정)

연결과 쓰기를 네 단계로 나눠 따로 센다. 한 단계의 0이 다른 단계의 0을 뜻하지 않는다.

| 단계 | 뜻 | 계측(실행기, 역할별) |
| --- | --- | --- |
| ① 연결 생성 | 실제 드라이버 호출이 연결을 만든 횟수 | 보호 드라이버 호출 수(서버 `log_connections`와 대조) |
| ② 제품 인계 | 공급자 관측·판정을 통과해 제품 함수에 연결이 넘어간 횟수 | 실행기가 `_product_connector`가 돌려준 연결 컨텍스트의 진입 성공을 감싸 셈(원래 함수는 그대로 호출) |
| ③ 업무 실행 | 인계된 연결에서 실행된 문장 수(첫 낱말 `SELECT`·`INSERT`·`UPDATE` 등으로만 분류)와 `COMMIT` 수 | 인계 뒤에만 켜지는 문장 계측. 지원 범위는 연결·커서 `execute`의 문자열·`psycopg.sql` 객체이며 SQL 파서는 아니다(`executemany`·여러 문장 묶음 미지원) |
| ④ 커밋된 변경 | 검사 전후 DB 행 내용 차이 | 관리 연결의 표별 열 값 해시, `srs_migration_runs`·`srs_migration_snapshots` 행 |

- 거부 위치에 따른 기대값:
  - **연결 전 거부**(사전 검사·입력·근거·계획 파일): 해당 역할 ① 0.
  - **관측 후 거부**(b2·b3·c1 ②처럼 공급자 관측에서 거부): ① 1 이상 허용, ② 0, ③ 0, ④ 0. 연결 0회를 요구하지 않는다.
  - **제품 잠금 아래 거부**(f1·f2의 `migration_run_exists`): ① 1, ② 1, ③은 잠금·실행 행 조회 문장만(`INSERT`·`UPDATE` 0), `COMMIT` 0(롤백), ④ 0(그 실행에 귀속되는 변경).
  - **드라이버 제약 실패**(f4): ② 1, ③에 `INSERT` 시도 1, `COMMIT` 0, ④ 0(그 실행에 귀속되는 변경).
- 무변경 판정은 두 가지로 나눈다.
  - **경합 없는 거부의 전체 DB 불변**: 검사 DB 업무 표 전체의 열 값 해시와 두 실행 표 행이 전후 같다. 승인된 관리자 변경(d2의 카드 변경, 권한 변형)은 기록한 그 차이만 빼고 비교한다.
  - **경합 중 거부된 실행에 귀속되는 변경 0**: 상대 실행(A)의 정상 변경은 위반으로 세지 않는다. 대신 ⓐ 해당 키의 실행 행이 정확히 1개이고 A의 범위·시작 기록과 같음 ⓑ snapshot 수 = A의 `applied` 수 ⓒ 각 카드의 `srs_card_version` 증가가 A의 결과와 같음(두 번 적용 없음) ⓓ 거부된 실행(B·C)의 인계 연결 `COMMIT` 0을 모두 만족해야 한다.
- 무변경은 **행 내용** 기준이다. 잠금 기록(`xmax` 등), identity 시퀀스 소비(f4의 실패한 `INSERT`는 값을 소비할 수 있음), 통계·WAL은 포함하지 않으며 이들이 무변경이었다고 일반화하지 않는다.
- 기대값은 실행 전에 고정하고 결과에 맞춰 바꾸지 않는다.

## 5. 근거와 판정

- 기대 권한은 계약 표(코드 상수)로 사전 고정한다. 관측값을 기대값으로 채택하지 않는다(c1 포함).
- C10 근거는 시험 키로 만든 **합성 서명 진술**이다. `backup_artifact_checked`·`restore_verified`는 계속 `false`이며 C12 결과를 실제 백업·복원 검증으로 표현하지 않는다.
- 분류와 중단:
  - **준비 실패**(클러스터·TLS·역할·DB·스키마·자료가 계획대로 안 됨, 의도한 후보 품질이 안 나옴): 검사 시작 전 중단, 실제 통과 0으로 기록.
  - **시험 장치 결함**(실행기 예외, 탐침 실패, 원복 실패, 대기 상대 증명 실패, 기록 실패): 그 검사 실패, 이후 검사 중단(증거 불완전이므로 제품 판정 안 함).
  - **제품 결함**(기대 결과와 다른 제품·CLI 결과): 그 검사 실패로 기록하고, 대상 자료가 오염되지 않았으면 다음 검사(새 DB) 계속. 제품 코드는 고치지 않는다.
- 준비 관문(G0: 대상·권한·관측 대상 목록·자료 품질 확인)과 실제 검사 통과 수는 따로 집계한다. 각 검사는 결과 기록이 디스크에 저장·재읽기 확인된 뒤에만 통과로 센다.
- 실행기 종료 코드: 선택한 모든 검사가 통과·기록됐을 때만 0. 실패·기록 실패·미완료·중단은 1. 사용법 오류는 2.
- 증거 항목(비밀값·원문 SQL 매개값 없음): `record.json`, `target.json`(연결 전후 대조 결과), `server.log`(연결·종료만), `results.json`(검사별 고정 코드·종료 코드·역할별 ①~③ 계수·`phase`·④ 행 해시 전후·실행 행 상태), `locks.json`(f2·f4의 PID·역할 이름·잠금 종류·모드·`granted`·`pg_blocking_pids`), `privileges.json`(관측 권한 전후와 변형·원복 기록). 실행 중 위치 `C:/JV_Tools/pg65/runs/<실행ID>/`, R2 전에 이 세션 임시 폴더의 `pg65_evidence/`로 복사하고 파일 크기·SHA-256을 REPORT에 남긴다(장기 보존 위치는 사용자 지정).
- 정리 확인 항목: 서버 정지, 55492 리스너 없음, `C:/JV_Tools/pg65` 없음, 비밀 작업 폴더 없음, 시험 서명 키 삭제, 기존 PG·`pgdata-e2`·기존 임시 폴더 불변.

## 6. R2 정리 (C12-4)

- 생성 기록과 현재 관측(PID·실행 파일·리스너·데이터 경로·`system_identifier`·DB/역할 OID)이 모두 같을 때만 진행한다. 다르면 아무것도 지우지 않고 중단한다.
- 순서: 시험 역할 세션 0 확인 → `pg_ctl stop -m fast` → 이번 실행이 만든 경로(`pg65`, 비밀 작업 폴더)만 삭제. 클러스터 단위 삭제이므로 DB 객체 개별 `DROP`은 하지 않으며, 실행 중 일시 객체·권한의 원복에도 `CASCADE`를 쓰지 않는다.
- 기존 `C:/JV_Tools` 항목, 기존 임시 폴더(`jp_vocab_c1_*` 포함)는 건드리지 않는다.
