# FSRS 교체 승인 기록

일자: 2026-10-09, Asia/Seoul.
사용자 원문: 'ㅇㅇ 숭인하고 작업지시 프롬프트 ㄱㄱ'.
직전 권장 승인안과 Gate B-1 실행 범위에 대한 승인이다. 이번 기록은 제품 구현/검증이 끝났다는 뜻이 아니다.

## 승인된 방향

1. `fsrs==6.3.2`, 기본 파라미터, 유지율 0.90, 최대 365일, fuzz 끔.
2. 학습 `(1분, 10분)`, 재학습 `(10분,)`. 첫 Good은 10분 뒤 재확인, Easy는 단계를 건너뛸 수 있음. 실제 실행으로 검증한다.
3. 학습 완료 조건은 Review + S>=30일 + 마지막 Again 이후 서로 다른 서울 날짜 성공 2회 + 그중 실제 7*24시간 이상 간격 성공 1회. **시뮬레이션용 초안이며 결과 후 재승인한다.**
4. 자기분류와 복습 참여 분리. 기존 known 제외 의도/예약/평가 이력을 보존하며 명시 선택으로 재참여한다.
5. 하루 신규 목표 초기 20개. 추가량은 명시 선택, S1은 서버 최초 평가 집계 + 큐 재조회이며 여러 기기 엄격한 상한/초과량 한도를 보장하지 않는다.
6. 예약/claim(S2), TTL/자정/만료/유예 계약은 후속으로 분리한다.
7. 자유 복습은 SRS 예약을 바꾸지 않는 연습이다.
8. 기존 예약 유지, 불완전 이력은 다음 평가부터 새 추정. 짧은 간격만으로 불완전 이력을 단정/중복 제거하지 않는다. 의심 자료는 이전 검토 보고서로 제공하며 사용자용 검토 도구는 후속이다.
9. 기존 `/stats` UTC 응답 필드는 호환용으로 보존. 서울 일일 실적 필드를 별도로 추가해 화면의 '오늘'을 서울 기준으로 통일한다. Gate D에서 연결한다. 저장/엔진 시각은 계속 UTC다.
10. Gate B-1 시작 시 `codex/fsrs-srs-replacement` 생성 또는 같은 작업의 기존 브랜치를 재사용한다. 다른 작업 브랜치는 임의 전환/삭제하지 않는다.

## 지금 실행할 범위

Gate B-1: 정확한 의존성 고정/엔진 어댑터, 완료 판정 함수, 추가형 저장 구조, 합성 테스트/시뮬레이션, 회귀 확인.
기존 runtime은 legacy로 유지한다. 스키마 추가가 새 엔진 활성화나 기존 known의 자동 보류 이전을 실행하지 않게 한다.
자료 이전 실행/평가 API 전환/실제 동적 큐/화면 교체는 다음 게이트다.

운영 DB 접근, 사용자 이력 이전, Gate B-2 이후 자동 진행, 스테이징/커밋/푸시/병합 승인은 포함하지 않는다.
기존 사용자 변경/미추적 자료를 보존하며, 자신이 만든 합성 임시 자료만 정리한다.

문서 충돌 시 이 승인 기록과 `gate-a/DECISIONS.md` 9절이 승인 이전 초안보다 우선한다.
