## 2. 지표 정의, 출처, 범위

### 정의
- **지금 복습** = `learning_due + relearning_due + review_due`(`/study-queue` counts). 새 단어는 넣지 않습니다.
- **오늘 새 단어 a / 목표 b**는 `/study-queue`의 `new_goal`에서 옵니다.
  - 정확(exact)이면 숫자를 보여 줍니다.
  - 확인 불가(unknown)이면 "확인할 수 없음 (적어도 n개)"처럼 하한만 보여 주고 0으로 쓰지 않습니다.
- **학습 상태 분포**
  - [보정] 정상 7분류: learning_due, relearning_due, review_due, pending_later, new_available, new_unmaterialized, paused(보류, 막대로 따로 표시).
  - [보정] 제외 5분류: not_converted, unsupported_config, invalid_state, blocked_history, missing_due.
  - (첫 보고서는 6/6으로 적었으나 실제 코드 `srsMetrics.ts`는 7/5입니다. 보류는 지금 복습에서는 빠지지만 분포에서는 정상 상태 행으로 보입니다.)
  - 제외 분류는 "복습에서 빠진 단어"로 따로 나열하며 정상 분류에 합치거나 버리지 않습니다.
  - 합이 `total_in_scope`와 다르면 안내 문구를 붙입니다.
- **오늘 평가(서울)** = `/stats.today_seoul.reviews`.
  - 개인과 구독을 나눠 셉니다.
  - 시각을 읽을 수 없는 로그가 있으면 unknown으로 두고 `at_least`를 표시합니다.

### 표시 상태
네 상태를 모든 화면에서 구분합니다.

| 상태 | 표시 |
|---|---|
| 확인 중 | "확인 중", 0을 먼저 보이지 않음 |
| 실패 | "확인할 수 없음" |
| 확인 불가(unknown) | 하한과 함께 표시 |
| 실제 0 | 0 |

| 화면 | 출처 | 범위 |
|---|---|---|
| 홈 복습 영역 | `/study-queue?limit=1` | [보정] 계정 전체(`deck:all`, 복습 탭 덱 선택과 무관). 홈에서 시작하는 FSRS 회차도 `scope=all` |
| 학습 준비 화면 한 줄, 학습 상태 패널 | 같은 항목 공유(`deck:<id>`) | 홈과 동일 |
| 통계 탭 분포·지금 복습 | `/study-queue?limit=1`(`deck:all`) | 계정 전체(개인 + 구독) |

| 단어장 지금 복습 칩·필터 | `/study-queue`(개인 덱) + `/vocab?due_only` | 단어장에서 고른 개인 덱 |

- 학습 계획은 first-review-v1, 본 단어/전체, 첫 복습 ETA를 바꾸지 않았습니다.
- 완료 수치와 완료 ETA는 어디에도 표시하지 않습니다(D-C2).

### 레거시 계정
- 홈은 기존 `/stats.due_today_count`를 그대로 씁니다.
- `/stats` 실패 시 0 대신 "확인할 수 없음"을 표시합니다(이번에 고친 부분).
- 복습 시작 동작과 요청은 바뀌지 않았습니다.

### 숨김
- 정렬 "복습 단계 낮은순"은 FSRS에서만 숨깁니다.
- 이미 그 값이 선택된 상태에서 FSRS로 판정되면 `next_review_asc`(다음 복습 빠른순)로 바꿉니다. 저장 키는 그대로입니다.
- `SharedDeckSection`은 review_level을 받지만 화면에 표시하지 않아 숨길 것이 없었습니다.

### 보호
- 지표 조회는 별도 GET(limit=1)입니다. 현재 세션의 대기열, 카드, 출제, 시도를 바꾸지 않습니다.
- 계정 epoch와 키별 순번이 다른 응답은 버립니다. 계정 경계에서는 숫자를 즉시 지웁니다.
- 409 `srs_mode_not_fsrs`를 받으면 모드를 다시 확인합니다.
- 서울 자정 타이머와 앱 복귀(visibilitychange) 때 다시 조회합니다. 현재 카드와 세션은 유지합니다.
- 평가 저장 후에도 지표만 다시 읽습니다.

## 3. API 호환
- `/stats`
  - 기존 UTC 필드(`reviewed_today_count`, `today_*_count`, `due_today_count` 등)의 이름, 의미, 값은 그대로입니다. 테스트로 확인했습니다.
  - `today_seoul`은 추가 필드입니다(스키마상 선택, 기본 None).
  - `today_seoul`은 `deck_id`가 있어도 계정 범위입니다(`scope: "account"`).
  - `today_seoul`의 키:
    - `date`, `timezone`, `scope`
    - `reviews{status, total|null, at_least, personal, subscribed, by_rating, unreadable_time_logs}`
    - `introduced{status, count|null, at_least}`
- `/vocab?due_only=true`
  - FSRS 계정에서만 의미가 바뀝니다. [보정] 큐의 `classify()`가 learning_due·relearning_due·review_due로 분류한 개인 카드만 남깁니다(8절).
  - 레거시 계정은 기존 규칙 그대로입니다.
  - [보정] 첫 보고서의 "남은 차이"(손상 카드가 목록에 섞일 수 있음)는 실제 결함으로 재현되어 고쳤습니다(8절).
- `/study-queue`: 서버 변경은 없습니다. 프론트가 `limit=1`을 보낼 뿐입니다.

  - 진행 중 세션의 카드와 개수는 유지되었습니다.
  - 클라이언트 자정 타이머 자체는 단위 테스트로만 확인했습니다(아래 7절).

### 8-4. 보호 확인(브라우저)
