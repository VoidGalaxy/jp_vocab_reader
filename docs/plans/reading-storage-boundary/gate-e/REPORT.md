# Gate E 보고: 안내 배치 보정과 최종 검증

작성: 2026-10-08. 브랜치 `codex/reading-storage-boundary`, HEAD `c4dd25c`. 스테이징·커밋·푸시·병합은 하지 않았다. 최종 승인 대기.

## 1. 안내 배치 보정

**한 줄 안내**
- 읽기 지면 바로 위에 한 줄(최소 높이 44px)만 둔다. 가장 중요한 상태 하나를 보여 주고, 나머지는 "외 N건"으로 센다.
- 중요한 실패 상태는 강조색과 `role="alert"`로 항상 보인다: 쓰기 실패, 다른 창 충돌, 확인 실패, 깨진 자료, 저장소 접근 불가.
- 덱 확인 필요, 미저장 편집, 미지원, 복사 제안은 일반 안내다.
- 저장 실패 문장은 이 한 줄과 상세로 옮겼다. 원인과 이전 저장본 유무는 상세에서 보여 준다. ReadingTab 안의 기존 경고 자리는 비워 두어 같은 안내가 두 번 나오지 않는다.

**"자세히" 대화상자**
- 긴 설명과 복구 버튼은 모두 이 대화상자 안에만 있다.
- 열면 첫 단추에 포커스가 가고, Tab·Shift+Tab은 안에서만 돌며, Escape는 닫기다. 닫히면 "자세히" 단추로 포커스가 돌아간다.
- 전환 확인창도 같은 틀을 쓴다. 첫 포커스는 "머무르기"이고, 닫히면 계정 메뉴 단추로 돌아간다.

**장면 가용 높이**
- 한 줄 안내의 높이(바깥 여백 포함)를 `--reading-notice-space`로 측정한다. 안내가 없으면 0px이다.
- 데스크톱(1024px 이상)은 프레임 높이, folio 렌더 높이, 세로 오프셋이 모두 `100svh − 50px − 안내 높이`를 같은 기준으로 쓴다. 그래서 배경·안전영역·좌·우 페이지 좌표가 함께 줄어든다.
- 폰(640px 이하)은 프레임 높이가 `100dvh − 70px − 안내 높이`다.
- 태블릿(641~1023px)은 원래 폭 기준 비율 프레임에 문서 스크롤을 쓰는 구성이라 높이 계산이 없다. 안내 높이만큼 문서가 길어진다(아래 표 참고).
- 태블릿·폰에서는 장면 위로 올라오는 "원문 읽기" 머리표와 겹치지 않도록 한 줄 아래에 18px 여백을 둔다. 이 여백도 측정값에 포함된다.

**변하지 않은 것:** 배경 에셋, 디자인 방향, 안전영역 수치, 다른 탭.

## 2. 캡처 비교 (`gate-e/shots/`)

합성 계정(ALPHA), 합성 원문, 세션 전용 SQLite, QA origin(3010)에서 찍었다. 한 줄 안내는 쓰기 실패를 주입해 띄웠고, 상세는 "자세히"를 연 상태다. 캡처에는 합성 원문과 학습 단어가 보이며, 실제 사용자 원문·인증 토큰·비밀번호는 없다.

| 폭×높이 | 안내 없음 | 한 줄 | 상세 | 측정 |
| --- | --- | --- | --- | --- |
| 1280×900 | `1280-none` | `1280-line` | `1280-details` | 안내 54px, 프레임 850→796px, 문서 넘침 0, 가림 0 |
| 1024×768 | `1024-none` | `1024-line` | `1024-details` | 안내 54px, 프레임 718→664px, 문서 넘침 0, 가림 0 |
| 800×1100 | `800-none` | `800-line` | `800-details` | 기존 문서 스크롤 339px, 안내로 +64px(=403px). 프레임 높이 1345px 그대로(비율 프레임), 가림 0 |
| 390×844 | `390-none` | `390-line` | `390-details` | 안내 68px, 프레임 774→706px, 문서 넘침 0, 가림 0 |
| 320×720 | `320-none` | `320-line` | `320-details` | 안내 68px, 프레임 650→582px, 문서 넘침 0, 가림 0 |

- 모든 폭에서 가로 넘침이 없다. 안내 줄·상세·전환 확인창의 단추는 모두 높이 44px 이상이다.
- 데스크톱과 폰에서는 원문 영역 하나만 스크롤한다. 안내 때문에 문서 스크롤이 새로 생기지 않아 이중 스크롤이 없다.
- 폰의 단어 카드는 기존과 같은 하단 덮개다. 320×720에서는 안내가 있으면 원문 보임 영역이 68px 줄어든다.
- 겹침 측정은 안내 줄 사각형과 `main`의 단추·입력·선택 상자 사이의 교차를 셌다. 원문 영역 안의 단어 단추가 화면 밖에 있는 것은 그 영역 자체 스크롤이라 가림이 아니다.

## 3. 최종 기능 검증 (Chromium 실제 브라우저, 주입 포함)

| 항목 | 결과 |
| --- | --- |
| 저장이 잠금을 기다리는 중 새 원문 → 새 입력 | 대기하던 옛 편집은 쓰이지 않음, 옛 세션 삭제, 새 원문이 새 instanceId(rev 1)로 저장 |
| 초기화 삭제가 잠금을 기다리는 중 분류 초안 열기 | 삭제 뒤 초안 원문이 새 세션으로 저장, 화면에 옛 내용 없음, 초안 보존 |
| 같은 계정 재로그인 | 같은 세션 복원 |
| 다른 창의 같은 계정 토큰 교체 | 경계 처리 후 직전 편집 저장(rev+1)·같은 계정으로 다시 복원, 편집 유지 |
| 다른 창 같은 계정 편집 | 한 줄 "다른 창에서 바뀌어 자동 저장을 멈췄어요", 상세의 "저장된 내용 불러오기"로 해소 |
| 원문만 복사(방문자) | 서버 쓰기 0, 원문만 복원 |
| 전체 사본(B) | 덱 연결 비움, 한 줄 "덱을 확인해야…", 확인 전 상태 변경 서버 쓰기 0, 옛 공통 키 원값 동일 |
| 쓰기 실패: 용량 / 접근 거부 | 한 줄 "이 기기에 저장하지 못했어요", 상세에 원인별 문장과 "이전에 저장한 내용은 그대로" |
| 쓰기 후 확인 실패 | 한 줄 "저장했는지 확인하지 못했어요 · 자동 저장 멈춤"(앞선 쓰기 실패 안내 대체), 다시 확인 뒤 정상 |
| Web Locks 없음(A안) | 한 줄 "이 브라우저에서는 자동 저장되지 않아요" |
| 읽기 위치 | 데스크톱 0.45 새로고침 복원, 다른 탭 6개 왕복 뒤 유지 |
| 반복 단어 | 30회 등장 중 클릭한 한 곳만 강조. 새로고침 뒤 선택 카드만 복원되고 본문 밑줄은 없음(기존 계약) |
| 상세 대화상자 키보드 | 첫 포커스·Tab 순환·Escape·"자세히"로 포커스 복원 |
| 전환 확인창 키보드 | 첫 포커스 "머무르기", Tab·Shift+Tab 순환, Escape 머무르기, 계정 메뉴로 복원 |
| 콘솔 오류 | 없음 |

`/me` 500·네트워크 오류·401 주입, 분석·저장 지연, 덱 X/Y 경합, 삭제 확인 실패, 확인창 취소는 Gate D에서 같은 코드로 확인했다. 이번 Gate E에서 바뀐 것은 안내 표시와 아래 두 보정뿐이다.

**Gate E 중 보정**
- 확인 실패나 재확인 성공 뒤에도 앞선 쓰기 실패 안내가 남던 문제를 고쳤다. 저장소가 메모리와 같아지면 안내를 지운다.
- 폭 구간이 바뀔 때 안내 높이를 다시 재도록 했다.

## 7. 남은 위험

- 데스크톱·폰에서는 안내가 있을 때 책·종이가 안내 높이만큼 작아진다(1280에서 약 6%, 320에서 약 10%). 디자인 승인이 필요하다.
- 태블릿은 비율 프레임 구조상 안내 높이만큼 문서 스크롤이 늘어난다(기존 339px → 403px).
- 이미 서버에 도착한 요청은 되돌리지 않고, 화면 적용만 막는다.
- 실패 복구본과 확인창의 "계속" 보관은 이 창 메모리에만 있다. 새로고침하면 사라지며, 안내 문구로 알린다.
