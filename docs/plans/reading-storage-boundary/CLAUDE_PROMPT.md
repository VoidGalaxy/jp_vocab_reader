# 클로드 작업 지시: 읽기 저장 계정 경계

아래 지시는 **Gate A부터** 시작한다. 준비 문서가 존재한다고 저장 계약이 최종 승인된 것으로 해석하지 않는다.

## 전달할 프롬프트

현재 `codex/reading-storage-boundary`에서 읽기 원문·상태의 기기 저장 계정 경계를 준비해 주세요. 기준 제품 코드는 `c4dd25c`이지만 실제 HEAD·브랜치·미커밋 변경을 먼저 확인하세요. 기존 목업·이미지와 다른 도구의 변경은 보존하세요.

먼저 다음 문서를 읽어 주세요.

- [PLAN.md](PLAN.md): 권장 계약, 기존 코드 감사, 이전·실패·동시 작업 규칙.
- [QA_MATRIX.md](QA_MATRIX.md): 실제 검증과 통과 조건.
- [공통 인계](../../work-handoff.md): 데이터·검증·릴리스 경계.

이번에는 Gate A만 진행하세요. 합성 자료와 세션 전용 SQLite로 공통 키의 초기 복원, 계정 전환 중 자동 저장/분석/단어 저장 경합을 재현하고, 구현 파일 범위를 확정해 주세요. 실제 사용자 localStorage를 읽거나 Neon/운영 DB에 연결하지 마세요.

권장안은 백엔드 환경+계정별 저장과 별도 방문자 영역입니다. 기존 공통 자료는 자동으로 귀속·복원·삭제하지 않고 원값을 보존합니다. 사용자가 본인 자료임을 확인하고 빈 목적지에 명시적으로 복사하거나 다운로드하도록 설계합니다. 기존 목적지를 교체하는 기능은 제외합니다. 계정 확인·복원 완료 전 쓰기 금지, 모든 읽기 비동기 작업의 owner/epoch/세대 가드, 저장 실패 시 기존 값 보존이 필수입니다.

Gate A 보고에는 방문자 정책, 원문/전체 로컬 사본의 복구 차이, 저장 실패 후 전환 안내, 두 창 직렬화·브라우저 지원과 미지원 동작을 짧게 정리하세요. 필요한 복구 문구는 기존 지면에 최소한으로 보여 주세요. 새 배경이나 리디자인은 하지 않습니다.

제품 코드·저장 키·SRS·백엔드·스키마·학습계획 계약은 아직 수정하지 말고, 재현·설계 자료만 이번 계획 폴더의 `gate-a/` 아래에 남겨 주세요. 실제 원문·토큰·DB·비밀번호는 인계 파일이나 캡처에 넣지 마세요. 서버와 임시 DB를 정리하고 커밋·푸시·병합 없이 승인 대기 상태로 멈춰 주세요.

## 계약 승인 후의 다음 지시

Gate A 계약 승인을 받은 뒤 PLAN의 B~E를 순서대로 수행합니다. 저장 모듈과 순수 테스트부터 만들고, page 연결·계정 경계·읽기 자식 초기화·최소 복구 안내를 붙인 다음 실제 브라우저로 검사합니다. 범위 변경이 필요하면 먼저 이유를 보고하고, 새 SRS/API/서버 저장 계약을 섞지 않습니다.
