## 연결 규칙

- **owner 확정:**
  - `/me` 결과가 등록 계정이면 `user:<id>`, 토큰 없이 받은 dev 사용자면 방문자, 로그인 응답이면 그 계정이다. 모두 현재 account epoch에서 받은 결과만 쓴다.
  - 확인 전(pending)과 401이 아닌 실패에서는 읽기 지면 대신 "계정 확인 중 / 다시 확인"만 보여 준다. 이때는 복원도 저장도 하지 않는다.
- **복원:**
  - 확정된 owner의 v3 키만 연다. 경계에서 시작한 이전 owner 저장이 끝난 뒤에 연다.
  - 깨진 자료는 `corrupt`, 저장소를 읽을 수 없으면 `unavailable`로 둔다. 둘 다 자동 저장을 멈추고 원자료 다운로드·명시 삭제만 허용한다.
  - 복원 뒤 덱이 비어 있으면 같은 epoch의 덱 목록에서 기본 덱을 고른다.
- **자동 저장:**
  - 600ms 지연 저장이고, 창 안에서 한 줄로 직렬화한다.
  - 바뀐 내용이 없거나, 빈 영역을 처음 연 그대로면 저장하지 않는다. 그래서 복구 목적지가 막히지 않는다.
  - `conflict`·`unverified`·`corrupt`·미지원 상태에서는 멈춘다.
  - 실패 안내는 원인(용량·차단·잠금·반영 안 됨 등)과 이전 저장본 유무를 구분한다.
- **계정 경계** (로그인·로그아웃·만료·다른 창):
  - 이전 owner의 미저장 편집은 그 키에 묶인 메모리 복구본으로 두고, 그 키에 저장을 시도한다.
  - 원문·분석 원문·토큰·덱 항목·서버 IDs·선택·두 스크롤·안내·복원 알림·분석 진행·일괄 저장 표시를 비운다. 분석은 abort한다.
  - 뜻 수정·신고 창을 닫고, `ReadingTab` key를 바꿔 바구니·검색·옵션 상태를 새로 만든다.
- **수동 전환:** 로그인·로그아웃 직전에 지금 owner로 저장한다. 실패하면 머무르기 / 글 내려받기 / 그래도 계속을 묻고, 내려받기만으로는 전환하지 않는다.
- **다른 창:** 토큰 키의 `storage` 이벤트는 만료와 같은 경계로 처리한다. 지금 owner 읽기 키의 변경은 덮지 않고 충돌로 표시한다.
- **요청 가드:**
  - `{owner 키, account epoch, 읽기 세대}`를 기준으로 분석(응답·catch·finally·진행률), 상태 변경, 일괄 저장, 덱 항목 재조회, 전체 사본 덱 확인에 적용했다. 뜻 수정과 신고는 epoch로 가드한다.
  - 분석은 조각마다 보내기 직전에 문맥과 토큰을 다시 확인하고, 다르면 보내지 않고 멈춘다.
  - 이미 서버에 도착한 요청은 되돌리지 않는다. 화면에만 적용하지 않는다.
- **복구 UI:**
  - 빈 영역이고 옛 공통 자료나 방문자 자료가 있을 때만 안내한다. 원문만(기본) / 분류까지(보조) / 원자료 내려받기 / 닫기 중 고를 수 있다.
  - 복사 전에 본인 자료인지 확인하고, 빈 목적지에만 복사한다. 원본은 지우지 않는다.
  - 전체 사본은 덱 연결을 비워 저장한다. 사용자가 "‘덱 이름’ 덱으로 확인"을 누르기 전에는 상태 변경·일괄 저장을 막는다. 새로고침해도 이 확인을 다시 요구한다.
  - 확인한 뒤에는 서버에 있는 단어만 서버 사실로 바꾸고, 나머지는 가져온 로컬 분류로 둔다.
- **충돌:** 사용자가 고를 때만 저장된 내용을 불러온다(이 창의 글 내려받기 가능).
- **확인 실패:** "다시 확인"은 저장값이 이 창이 쓰려던 내용과 같을 때만 그 버전을 채택하고, 이어서 저장한다. 다르면 충돌로 둔다.
- **분류 초안 "읽기에서 열기":** 확인된 owner 영역에만 원문을 연다. 분석·삭제는 하지 않는다.

## 실제 브라우저 검증

검증 환경은 다음과 같다.
- 세션 전용 SQLite, 합성 계정 ALPHA·BETA, 합성 원문(`〔표지〕`).
- QA origin `http://localhost:3010`(사용자 앱과 분리), 내장 Chromium 152.
- 옛 공통 키에는 합성 v2 자료를 넣었다. 다운로드는 앵커 클릭을 가로채 파일명·내용만 확인했다.

| 시나리오 | 결과 |
| --- | --- |
| 방문자 첫 진입 | 옛 자료 자동 복원 없음, 원값 동일, 빈 방문자 세션 생성 없음, 복사 안내 표시 |
| A 로그인 → 원문만 복사 | 확인 후 A 키(rev 1, 새 instanceId)에 원문만 복사, 서버 쓰기 0, 옛 키 원값 동일 |
| A → 로그아웃 → B → A | 방문자·B 화면과 키에 A 표지 없음, B에는 옛 자료 안내만, A 재로그인 시 A 복원 |
| A가 입력한 지 50ms 뒤 로그아웃 | 마지막 입력이 A 키에 저장됨, 방문자 화면에는 즉시 표시 없음, 방문자 키 생성 없음 |
| 저장 실패(용량) 후 로그아웃 | "용량 부족, 이전 저장본 그대로" 안내. 확인창에서 내려받기는 전환하지 않았고, 머무르기는 A를 유지. 계속하면 방문자로 전환되고 B는 깨끗. A 재로그인 시 "저장하지 못한 편집" 복구 → 되살리기로 저장 |
| 만료(위조 토큰) | 즉시 방문자 화면, A 내용 미노출, 실패 편집은 A 재로그인 때만 복구 안내 |
| 분석 첫 조각 6초 지연 중 B로 전환 | `/analyze`는 A 토큰 첫 조각 1건뿐, 두 번째 조각 미전송, B 화면 깨끗 |
| 상태 저장 POST 6초 지연 중 B로 전환 | 서버에는 A로 정상 귀속(200), B 화면·B 키 오염 없음 |
| 전체 사본 | 서버 IDs·저장 완료 제거, 덱 확인 전 상태 변경 서버 쓰기 0, 새로고침 후에도 확인 요구, 확인 뒤 B 덱에 POST·B 항목 ID 연결 |
| 새 원문(초기화) | 확인 후 현재 owner 키만 삭제, A·옛 키 그대로, 빈 세션 재생성 없음 |
| 같은 계정 두 창 | 다른 창 저장 즉시 충돌 안내, 이 창 편집이 덮어쓰지 않음, "저장된 내용 불러오기" 후 저장 재개 |
| 다른 창 로그아웃 | 이 창이 즉시 방문자 화면으로 바뀌고 이전 내용 미노출 |
| Web Locks 없음(`navigator.locks` 제거) | 복원은 됨, 미지원 안내와 내려받기만, 편집 저장 0, 미저장 상태 전환은 확인창 |
| 쓰기 후 확인 실패 | 확인 실패 안내, 이후 편집 저장 중지, "다시 확인"으로 채택 후 대기 중 편집까지 저장 |
| 분류 초안 읽기에서 열기 | 현재 owner(A)에 원문만, `/analyze` 0, 초안 보존 |
| 1280×900, 390×844 | 안내 카드·확인창 표시와 버튼 확인, 가로 넘침 없음. 390에서는 카드가 단어 카드 아래쪽을 가릴 수 있어 "접기"로 작은 단추로 줄일 수 있게 함 |

자동 검사: `npm test` 61/61, `npm run typecheck`, `git diff --check` 통과. 이번 Gate C용 page 단위 테스트는 추가하지 않았고, 위 브라우저 검증으로 대신했다.

## 미검증·남은 위험

- `/me`가 401이 아닌 오류를 내는 실패 상태는 코드로만 확인했다(페이지 로드 전에 오류를 주입하지 못함).
- 실제 비보안 컨텍스트(LAN IP), Firefox·Safari, 실제 용량 초과는 확인하지 않았다. 미지원과 실패는 주입으로만 재현했다.
- 수동 전환 확인창의 "다운로드"와 실패 복구본은 이 창 메모리에만 있다. 새로고침하면 사라진다(안내 문구로 알림).
- 전환 직후 이전 owner 저장이 다른 창의 저장과 겹치면, 그 저장은 conflict로 남고 복구본만 남는다.
- 390 폭에서 안내 카드가 화면 아래 일부를 가린다. 접기는 가능하지만 위치 조정은 디자인 판단이 필요하다.
- 1024·800·320 폭과 접근성 세부(포커스 이동·트랩)는 Gate D에서 본다.
