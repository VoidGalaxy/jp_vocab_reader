# 읽기 저장 경계 검증표

기준: 2026-10-08. [권장 계약](PLAN.md)의 구현 승인 후 수행할 검증이다. **이번 준비 단계에서는 아래 검사를 실행하지 않았다.**

## 데이터와 환경

- 세션 전용 SQLite, 합성 원문/토큰만 사용한다. 실제 localStorage·운영 자료·Neon 연결을 열람하지 않는다.
- 독립 브라우저 컨텍스트에서 계정 A/B, 방문자 G, 서로 다른 API 환경을 만든다. 같은 API URL 뒤 DB 재생성은 환경 분리 검사가 아니다.
- 원문/분석 원문/상태/읽기 위치/선택이 다른 자료를 각 영역에 넣는다. 미평가와 known 상태, 긴 글, 깨진 JSON, 미지원 버전도 별도로 만든다.
- 마운트 직후부터 owner가 확정될 때까지 DOM과 쓰기 호출을 표본 수집한다. 화면이 안 보인 것만으로 저장 오염까지 통과 처리하지 않는다.
- DB 쓰기는 명시적 분류·저장 테스트에서만 발생할 수 있다. 복원·복구 복사·다운로드에서 POST/PATCH/분석 호출은 0이어야 한다.

| 번호 | 시나리오 | 통과 기준 |

| 2 | `/me` 지연·실패·현재 토큰 401 | 계정 자료 추정 복원 없음, pending/실패 중 덮어쓰기 없음 |

## 회귀와 최종 검사

- 데스크톱 1280×900·1024×768, 태블릿 800×1100, 모바일 390×844·320×720.
- 새 분석 0% → 중간 위치 → 옵션/편집 왕복 → 다른 탭 왕복 → 새로고침. 원문·토큰 순서·선택·두 스크롤 분율을 비교한다.
- 반복 단어는 클릭한 위치 한 곳만 강조, 새로고침은 기존처럼 선택 복원·밑줄 없음. 이번에 정확한 등장 저장 계약을 추가하지 않는다.
- 분류·개별/선택 저장·이미 저장 안내·어휘 노트 이동·복습 시작·뜻 수정·신고를 기존 콜백으로 확인한다.
- 계정 A/B/방문자의 복습·학습계획·통계 경계가 약해지지 않는지 기존 회귀를 돌린다.
- 가로 넘침·잘린 버튼·의도치 않은 화면/스크롤 이동·콘솔 오류·실패 요청을 확인한다. 의도한 401/오류 주입은 따로 집계한다.
- `npm test`, `npm run typecheck`, SQLite 기본 테스트, SRS 회귀, `git diff --check`. QA 서버 종료 후 빌드 한 번. 테스트 수는 실제 결과를 적는다.
- 배포 코드의 QA 훅·실제 원문·토큰·DB·자동 다운로드·다른 key 삭제가 없는지 감사한다.
- 결과에는 실제/모킹 검증, 브라우저 지원 범위, 미검증, 서버·DB 정리 여부를 구분한다. 자료 내용은 로그 대신 합성 식별자·길이·비교 결과로 보고한다.
