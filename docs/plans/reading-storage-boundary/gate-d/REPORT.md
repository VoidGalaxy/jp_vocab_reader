## 결함 보정

1. **초기화·작업 교체가 이전 요청을 무효화하지 않음**
   - 읽기 작업 ID를 새로 두었다. 새 원문(초기화)·원문 교체(분류 초안 열기, 홈 샘플)·새 분석 시작·저장된 내용 불러오기·복구·복사가 모두 작업을 바꾼다. 분석은 abort하고, 일괄 저장 진행 표시와 덱 요청 순번도 무효화한다.
   - 분석·상태 저장·일괄 저장·재조회의 응답·catch·finally는 작업이 같을 때만 적용한다.
   - 초기화의 저장소 삭제는 저장 줄 뒤에 세워, 예약·진행 중인 저장이 끝난 뒤의 버전으로 지운다. 이전 세대의 예약 저장은 실행되지 않는다.
2. **다른 창 내용 불러오기·미저장 사본 되살리기에서 덱 확인을 건너뜀**
   - 최초 복원·불러오기·복사는 같은 적용 함수를 쓰고, 덱 연결 없이 토큰만 있으면 덱 확인을 요구한다.
   - 되살리기도 같은 규칙을 쓴다. 확인 전에는 저장 스냅샷의 덱을 비워 두므로 되살린 뒤에도 다시 요구한다.
3. **조회 중 덱 변경을 구별하지 않음**
   - 덱 확인과 재조회는 요청 당시 덱과 현재 덱이 같고, 그 요청이 마지막일 때만 적용한다. 분석·상태 저장·일괄 저장도 응답 시점에 덱을 다시 확인한다.
   - 사용자가 덱을 바꾸면 이전 덱 요청은 무효가 되고 진행 표시도 꺼진다. 오래된 finally는 마지막 요청이 아니면 진행 표시를 건드리지 않는다.
4. **삭제 확인 실패 안내가 부정확함**
   - 마지막 저장소 시도를 저장/삭제로 구분해 기록한다.
   - 삭제 확인 실패는 "지웠는지 확인하지 못했어요. 지워졌을 수도, 남아 있을 수도 있어요"로 알리고 자동 저장을 멈춘다.
   - "다시 확인"은 키가 없을 때만 지워진 것으로 채택하고, 남아 있거나 깨졌으면 충돌로 둔다.

## 그 밖의 보정

- **확인창 취소:** 수동 전환 확인창이 열린 중에 만료나 다른 창 계정 변경이 일어나면 확인창을 닫고 대기 중 전환을 취소한다. 저장을 기다리는 사이 계정이 바뀌어도 취소한다.
- **토큰 없이 받은 `/me` 401:** 만료 처리가 이어지지 않아 "확인 중"에 멈추던 것을 확인 실패("다시 확인")로 바꿨다.
- **뜻 수정·신고:** 같은 편집 항목·같은 신고 창의 마지막 요청일 때만 그 창의 상태와 안내를 바꾼다. 읽기 작업이 바뀌었으면 새 작업의 토큰을 건드리지 않는다.
- **복사 제안 정리:** 다른 창이 세션을 만들었거나 이 창이 처음 저장해서 목적지가 비어 있지 않으면 복사 제안을 거둔다.

## 미검증·남은 위험

- 안내 카드가 이제 지면 위쪽에 자리를 차지해서, 안내가 있을 때는 읽기 지면이 그만큼(약 110~150px) 아래로 내려간다. 가림은 없지만 첫 화면 구성이 바뀌므로 디자인 확인이 필요하다.
- 실제 LAN 비보안 컨텍스트, Firefox·Safari, 실제 용량 초과는 확인하지 않았다(주입으로만 재현).
- 이미 서버에 도착한 요청은 되돌리지 않는다. 화면 적용만 막는다.
- 순수 회귀 테스트는 page의 배선을 모사한 것이고, page 컴포넌트 단위 테스트 도구는 없다. page 동작은 브라우저 결과로 확인했다.
