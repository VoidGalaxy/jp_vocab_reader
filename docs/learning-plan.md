# 학습 계획 계약

기준: 2026-10-07, `433f04e`에서 연결하고 `0fb5a0f`에서 실행·계정 경계를 보강한 코드.

## 사용 흐름

덱 선택 → 시작일·목표일 → 하루 신규 단어 권장량 → 첫 학습 진도·예상일 확인 → 저장 → 학습 시작.

사용자가 보고 싶은 최종 방향은 기억이 안정된 학습 완료다. 현재는 그 기준을 정하지 않았으므로 **첫 평가 기준의 임시 참고 지표**만 제공한다. 화면의 첫 학습 완료는 숙련·암기 완료를 보장하지 않는다.

## 진도 정의

- 읽기 전용 `GET /learning-plan/progress?deck_kind=personal|subscribed&deck_id=...`를 사용한다. 로그인 필요, 남의 개인 덱·구독 해제 덱은 404다.
- `metric_version`은 `first-review-v1`. 응답은 `deck_kind`, `deck_id`, `total`, `seen`, `progress_scope`, 서울 `today`, `as_of`다.
- `last_reviewed_at`이 있는 단어를 접함으로 센다. 다시/어려움/보통/쉬움 모두 첫 평가 1개가 되고, 반복 평가는 개수를 늘리지 않는다.
- 읽기에서 아는/헷갈림/모름으로 상태만 바꾸는 것은 평가가 아니므로 접함 수가 늘지 않는다.
- 개인 덱은 자신의 카드 기준(`deck_cards`). 복사한 개인 덱은 복습 이력 없이 시작한다.
- 구독 덱은 계정+lexeme 공유 진도(`account_shared`). 다른 구독 덱에서 평가한 같은 단어도 접함에 포함된다.
- 덱 구성 변경은 현재 구성으로 다시 계산한다. 응답 미확인·오류·잘못된 숫자를 0으로 보정하지 않는다.

## 일정과 하루량

- 하루는 Asia/Seoul 날짜다. 시작일과 목표일을 모두 포함한다.
- 기준일 `B = max(시작일, 서울 오늘)`, 남은 기간 `D = 목표일 - B + 1`.
- 잔량 `R = total - seen`, 하루량 `Q`는 정수 0~500개다.
- `Q > 0`일 때 필요 일수는 `ceil(R / Q)`, 예상일은 `B + 필요 일수 - 1`이다. 기간 내 최소 권장량은 `ceil(R / D)`이며 500을 넘으면 조정값을 제안하지 않는다.
- 잔량은 현재 값을 쓴다. 오늘 아침 잔량으로 고정하거나 오늘 처음 학습한 수를 더하는 보정은 구현하지 않았다. 학습 중 예상일은 달라질 수 있다.
- 하루량은 신규 단어 **권장량**이다. 실제 큐 상한이나 평가 횟수 목표가 아니다.
- 0개는 신규 학습 쉬는 중이다. 첫 학습 마침과 함께 새 학습 대신 해당 덱의 오늘 복습 경로를 제공한다.
- 미래 시작일도 미리 학습할 수 있다. 기간이 지난 계획을 자동 연장하지 않는다.

## 저장과 계정 경계

- 백엔드 환경과 로그인 계정별로 이 브라우저에 활성 계획 하나를 저장한다. 서버·다른 기기 동기화는 없다.
- `learningPlanStorage.ts`가 날짜·덱·하루량을 검증한다. 깨진 자료를 조용히 삭제하거나 기본 계획으로 덮지 않는다.
- 같은 계정의 탭 왕복은 미저장 편집을 메모리에 유지한다. 새로고침 후에는 저장본 기준이며, 로그인·로그아웃·만료 때 편집 메모리를 비운다.
- 다른 창 저장과 미저장 편집이 충돌하면 안내하고, 편집을 조용히 덮지 않는다. 저장 실패 시 기존 계획을 보존한다.
- 이전 분류 초안은 별개 자료다. 내려받기·읽기에서 열기·삭제는 사용자 선택으로만 수행한다. 원문 자동 전송·분석·삭제는 하지 않는다.

## 학습 실행

- 미저장·입력 오류·조회 불가 등 명령 상태는 `LearningPlanSection.tsx`의 판단을 따른다.
- 진행 중 복습이 있으면 이어하기/바꾸기/취소를 묻는다. 바꾸기는 새 큐 조회 성공·비어 있지 않음·같은 계정·같은 기존 세션일 때만 적용한다.
- 실패·빈 큐·취소·중복 클릭·계정 변경·늦은 응답·조회 중 기존 세션 진행은 현재 세션을 덮지 않는다.
- 구독 신규는 `first_review_only=true`로 서버에서 미평가 단어를 먼저 거른 뒤 LIMIT한다. 상태가 known이어도 미평가이면 포함한다. 기존 구독 신규 조회 상한 30은 그대로이며 계획 하루량으로 다시 자르지 않는다.
- 개인 덱 신규도 `last_reviewed_at` 기준이다. 예정 복습과 신규를 동일하게 취급하지 않는다.

## 수정 경계

현재 계산은 `learningPlan.ts`, 저장은 `learningPlanStorage.ts`, 실행 보호는 `planStudyLauncher.ts`, 연결은 `LearningPlanPanel.tsx`와 `page.tsx`, 집계는 `learning_plan_repository.py`다.

SRS, 스키마, 저장 키, API 계약, 숙련 기준, 서버 동기화 변경은 디자인 보정으로 묶지 않고 별도 승인한다. PostgreSQL 실제 동작은 이번 로컬 테스트에서 확인하지 않았다.
